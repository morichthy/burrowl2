|---|---|

## 问题

AI 通过 MCP 查询 burrowl 时，人很难知道它这次用了 burrowl 的哪些东西、得到了什么认知、为什么在读；会话结束后也缺少可交接的材料。

## 决定

| # | 决定 | 理由 | 放弃的做法 |
|---|---|---|---|
| D-01 | **"读了什么"不另存**：读时从读取记录（`reads`）、检索命中记录（`search` 事件）和本会话写的判断算出。分三类：读过原文的原件、检索命中但没读原文的条目（标"参考过"）、写下的判断 | 这些事实已在账本里；另存一份会与账本不一致 | 让 AI 自己列"我读了什么"（自评不可信） |
| D-02 | **目的、认知、handoff 是 AI 的会话笔记**，写成会话内只追加的过程事件 `reading.note`（`source_class=inferred`）。每次只带要更新的字段，各字段取最新一次给出的值；认知整份替换，可带依据条目 `refs` | 不加表、不加迁移；属过程内容，不能作为结论的依据（I11）；账本只追加（I1）保留笔记历史 | 框架库新表（要迁移、导出导入、删除范围，且与"可再生的框架"不符）；写成判断（把过程笔记混进依据链） |
| D-03 | **handoff：快照 + 实时读登记的文件**。AI 提交内容快照；agent 已有自己的 handoff 文件时，在 `handoff_source` 登记它的绝对路径，人在工作台点击"阅读 handoff"时由 `reading.handoff_file` 实时读这个文件（展开期间每 3 秒刷新），读不到退回快照；没有文件就由 AI 直接写。没有 handoff 时给一条"让 AI 补一份"的提示可复制（先做快照，用户随后决定加实时读） | 用户要求能实时看 agent 自己的 handoff。读取的安全边界：只读该会话最近登记的那个路径、须是已存在的绝对路径、`.md/.markdown/.txt`、不超过 512 KB、只在人点击时读、MCP 不能调用（`reading.handoff_file` 对非 HTTP 入口报 FORBIDDEN） | 只给快照（agent 文件改了就过期）；让网页读任意路径 |
| D-04 | **只有 AI 能写笔记**（`reading.note` 对人报 FORBIDDEN）；人想记录请写判断或登记原件。巡检会话不能写（同 `guard_original_write`） | 笔记的含义是"AI 自己说它在做什么" | — |
| D-05 | **要求 AI 维护**：MCP instructions 与 RULES 写明；检索结果的 `hints` 在 AI 还没写过笔记时、或上次笔记后又用了 5 次检索或读取时提醒 | 程序只能提醒，不能强制 AI 写；提醒只给 AI，不影响人的检索 | 不写就拒绝检索（会堵死正常使用） |
| D-06 | **展示**：首页右栏"阅读会话"卡片（最近 5 个：目的、读原件数、检索数、认知条数、是否有 handoff）；`#/reading` 列表；`#/reading/<会话>` 详情（目的、认知、读了什么、检索记录、Handoff） | 首页本来就是"今日"，右栏放进行中的事 | 放进待你处理通栏（会挤占三列概览） |

## 对不变式与影响表的影响

不碰 I1–I12：不新增账本表、不改旧行；笔记是过程事件，I11 仍成立；操作 `reading.note` 为 write、`reading.list` / `reading.get` 为 read，MCP 一律是 AI（I4）。新服务 `services/reading.py`（RDG）进影响表；`reading.` 前缀并入 `INTERNAL_OPS`（系统流水，不触发"操作前未检查约束"）与 `purge.SYSTEM_OPS`（删除原件时一并清理提到它的笔记）。

## 已知差距

- 没有记录 `entry_get`、`entry_expand` 等不留读取记录的调用，所以"读了什么"只含读取记录、检索命中与写下的判断。
- 会话 ID 沿用 MCP 客户端的会话；同一个 agent 重启后是新会话。
- 实时读只在 MCP 与工作台在同一台机器、路径登记的是绝对路径时有效；跨机器、相对路径、插件名、超过 512 KB 或后缀不符时退回快照。AI 的登记路径由 AI 填写，工作台只读它登记的那个文件，但不判断文件内容是否敏感；人点击前可从详情页看到路径。
