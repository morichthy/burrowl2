## 1. 背景（2026-11-09）

现有机制只在**有变化时**提醒：依据变了，下游框架标"输入已变化"，判断进"待复核"。下面几类问题不会自己冒出来：

| 问题 | 例子 | 现在为什么发现不了 |
|---|---|---|
| 原件与结论冲突 | 同一设备、同一条件下，两条结论的结果相反，却没有 opposes 或可能矛盾边 | 写判断时只校验依据存在，不比较内容 |
| 结论遗漏了原件里的东西 | 结论只引了第 3 节第 2 段，同一节第 4 段写着"仅在常温下成立"，从没被读过 | 读取记录只记读了什么，不提示没读什么 |
| 条目与规则不符 | 判断里写"根本原因是……"（[草图](../model/DESIGN-SKETCH.md) §4 不允许）；对象、条件为空；规定和实际操作对不上 | 写入时只拦依据层级、过程内容作依据这几项硬规则 |
| 有用的描述反复被遗漏 | 某一段每次都出现在检索结果里，但 AI 从不打开 | 没有任何记录能看出"命中了但没读" |

## 2. 原则

1. **先规则、后 AI**：能由系统按规则查出的可疑项先查出来，AI 只看规则圈出的范围与少量探索样本。费用可控，范围可重复，也便于评测。
2. **两道 AI 检查，都由人发起**：巡检员提出发现，复核员自己重新读原件后给出意见；最后由人处理。任何一道都不写回判断层（I1、I5，设计稿 04 D-08）。
3. **巡检发现是框架内容**：可以丢弃、不能作为依据（I2），带复核状态。
4. **覆盖图是工具，不是指标**："没读过"不等于"有用"；不把覆盖率当作要提高的数。
5. **人决定什么能发出去**：标为不外发的原件，原文不进巡检包。

## 3. 决定

### 调度与调用边界

| 编号 | 决定 | 理由 |
|---|---|---|
| D-01 | **定时只准备，人点开跑**（用户决定，2026-11-09）。到期时系统（`system:inspection`）在本机做规则检查与抽样（D-05 至 D-10），生成一份**巡检包**；首页"待你处理"显示"本期巡检已准备好：N 项可疑、M 处冷区抽样"，人点"开始巡检"才用设置里的巡检员 agent 走 `agent.start`，发起人记为人 | 定时环节不调用大模型，符合约束 7 / I12，不需要修订设计稿 05 §2；启动 agent 本来就只能由人做（I5） |
| D-02 | **复核员也由人启动**（用户决定，2026-11-09）。巡检员运行结束后不自动启动复核员；待决策页按巡检运行分组，组标题上有"交给复核员"（也可以多选发现），用复核员 agent 走 `agent.start` | 同 D-01 |
| D-03 | **调度**：沿用 `interfaces/pool.py` 的定时检查，与原件检查共用。设置 `inspection.interval_days`（默认 7，0 关闭）；人也可以随时点"现在准备巡检包"（阶段收口时用）。上一期的巡检包没处理完时，到期只更新它，不另起一期 | 不另造调度；避免巡检包堆积 |
| D-04 | **范围**：上一期巡检包生成以来新增或有变化的判断（含新版本）、它们引用的原件，加上 D-09 的探索样本。第一期取最近 30 天 | "近期研究"有可核对的边界 |

### 规则检查（系统做，本地）

每项检查产出一个**巡检任务**：检查项、涉及的条目与版本、要读的段落锚点、一句要回答的问题。巡检任务只说明"这里可疑"，本身不是发现。

| 编号 | 检查项 | 规则 |
|---|---|---|
| D-05 | **疑似冲突** | 两条结论共享对象，条件字段可以对齐且不冲突，结果或正文含相反表述（否定词、数值方向相反、取值不同），彼此之间既没有 opposes / supersedes / 条件并存的链接，也没有可能矛盾边。只按结构与字面比较，不调用大模型；可以用本地向量模型找候选对（约束 7 允许） |
| D-06 | **相邻段落未读** | 结论引用了某个段落，而同一小节（没有小节时取前后各 2 段）里有段落从没被任何读取记录覆盖；或者依据的边界为"截断""只读了一部分" |
| D-07 | **与规则不符** | 判断正文含草图 §4 列出的评价性措辞或框架性写法（"显然""关键在于""根本原因是""目前有三种思路"等，词表放在设置里，可以增删）；对象或条件为空；结论只有一个依据来源且为推断；规定（normative）所针对的对象，在过程日志里有它生效后、未调用约束检查的操作（复用"操作前未检查约束"） |
| D-08 | **依据变化后仍被引用** | 引用了待复核判断、已退役原件、带未确认识别文字的段落的结论（汇总已有的 `RECHECK_CITATION`、`RETIRED_CITATION`、`LOW_FIDELITY_CITATION` 提示，只列本期范围内的） |

### 覆盖图与扩大阅读范围

| 编号 | 决定 | 理由 |
|---|---|---|
| D-09 | **探索样本**：巡检包的阅读预算（`inspection.max_segments`，默认 60 段）按比例分配，`inspection.explore_ratio`（默认 0.3）用于探索。从覆盖图的"命中未读"与"相关未读"两档中抽样，权重为"与本期判断的相关度 × 距上次被读或被抽中的时间"；抽中的段落记在巡检包里，下次权重降低。每个探索样本是一个任务，问题固定为"这一段里有没有本期结论应当考虑却没有考虑的内容" | 让阅读范围逐期扩大，不总在同一批段落里打转 |
| D-10 | **覆盖图**（新页面，也是 `coverage.view` 只读操作）：每份原件的段落按以下五档着色，可以按原件 × 段落看格子，也可以按对象汇总；点一格打开那一段原文，并列出读过它的会话、引用它的判断、命中它的检索 | 让人看到盲区在哪里 |
| D-11 | **五档的口径**：① 被引用（`cited_segments`）；② 读过未引；③ **命中未读**：在 `inspection.window_days`（默认 90 天）内被检索返回不少于 3 次，从没被读；④ **相关未读**：与本期判断的向量相似度高于阈值，从没被读；⑤ 冷区：其他。已退役的原件不计入 | 只用已有数据和 D-12 的检索命中记录就能算出 |
| D-12 | **检索命中记录**：AI 调用 `search`、`search_associate` 时，在过程日志里记一条 `search` 事件，只记查询文字、模式、返回的条目 ID 与命中段落锚点（前 20 个），不记全文；工作台里人的检索不记。`search` 加入 `INTERNAL_OPS`，不进入默认检索 | 现在检索不留记录，"命中未读"无从统计；过程日志本来就应保存所有操作（草图 §2） |
| D-13 | **覆盖图是框架内容**：每次从读取记录、引用、检索命中记录与向量算出，不单独存储，不能作为依据；不在首页显示覆盖率数字 | 原则 4 |

### 巡检包与巡检发现

| 编号 | 决定 | 理由 |
|---|---|---|
| D-14 | **巡检包**存在框架库新表 `inspections`（编号 `insp_…`）：期次、生成时间、范围、任务清单、状态（准备好 / 巡检中 / 巡检完成 / 已关闭）、各次运行的 `run_id`。巡检包可以重新生成，生成规则升级时旧包照常可读 | 框架库可以修改，适合放有状态的计划 |
| D-15 | **领取与提交走 MCP**：新操作 `inspection.get`（effect=read）返回巡检包与任务说明；`inspection.submit`（effect=write）提交巡检发现。巡检员按任务调用 `artifact_read` 读原件，读取记录照常留下。启动巡检员时的提示只有一句：领取哪一期、按说明完成 | 原文不必塞进提示词，也不会在复制时截断；过程可追溯 |
| D-16 | **巡检发现**（用户决定为框架内容，2026-11-09）：框架库新表 `findings`（编号 `fnd_…`），字段为所属巡检包与任务、检查项、涉及的条目及版本、引用的原件段落、说明、建议的处置（写反对判断、请人更正、补读某段、建可能矛盾边、无需处理），作者为巡检员这次运行的 AI，复核状态初始为"AI 生成未复核"。不能被引用（`JudgmentService.basis_of` 拒绝 `fnd_` 前缀），不进默认检索 | 发现是对已有条目的组织与推断，可以丢弃；写成判断就再也撤不掉了 |
| D-17 | **提交的限制**（与 `review.ai_submit` 一致）：发现引用的段落必须在本会话读过；依据只能是原件层和判断层；不能针对本会话自己写的条目。不满足的拒绝 | 防止巡检员凭检索摘要下结论 |
| D-18 | **发现涉及判断时**：`inspection.submit` 同时为被指出的判断调用 `review.request`，开一项复核待决策（`requested=True`，附发现编号）；发现涉及两条判断冲突时，另建一条可能矛盾边（AI 推断，两端都是判断，按设计稿 04 D-08 只能由人确认） | 用现有机制走通；原判断不改，复核结论记进它的复核历史（设计稿 04 D-18） |
| D-19 | **去重**：每条发现记指纹（检查项 + 涉及的条目 ID 与版本 + 引用的段落）。人驳回或忽略过的发现，指纹相同时下一期不再生成任务；涉及的条目出了新版本，指纹自然改变 | 避免每期冒出同一批 |

### 复核员与人的处理

| 编号 | 决定 | 理由 |
|---|---|---|
| D-20 | **复核员用 `review.ai_submit`**，对象增加巡检发现 `fnd_…`；对发现开出的判断复核项照现有规则处理（要求 `review.ai=all`，不能和写那条判断的是同一会话）。复核员每次运行是新会话，自然不会复核巡检员同一会话写的发现 | 不另造一套 AI 复核 |
| D-21 | **复核员必须自己读**：对发现给出 `confirm` 时，发现引用的段落必须在复核员的会话里读过（现有"先读后复核"）；只读了检索摘要的拒绝 | 二次检查要独立于巡检员看到的内容 |
| D-22 | **待决策页**：按巡检运行分组，组标题显示运行编号、时间、巡检员 agent、"N 项发现，复核员还没看过 K 项"；每项标出复核员的意见（确认 / 驳回 / 拿不准）；可以只筛出巡检员与复核员意见不一致的项；复核员确认的排在前面，驳回的折叠 | 人先看两道检查都认为有问题的 |
| D-23 | **人的处理**：对一条发现，人可以"采纳"（发现里列出针对的条目链接，打开后用复核、更正 / 撤回、确认可能矛盾），"驳回"或"忽略"（记入去重，D-19）。处理记在框架库的只追加表 `finding_reviews`（实现修订：原定账本 `reviews`，见 §8），关闭对应的待决策项 | 采纳后的实际修改仍走原有的人工入口 |
| D-24 | **巡检包关闭**：全部发现都有人的处理，或人点"关闭本期"，巡检包状态改为已关闭；未处理的发现保留在待决策里 | |

### 主、辅 agent 的设置与测试连接

| 编号 | 决定 | 理由 |
|---|---|---|
| D-25 | **设置页"巡检"组**：巡检员 agent（辅，可以用便宜一些的模型）、复核员 agent（主），各从 `config.json` 的 `agents` 里选；周期、阅读预算、探索比例、检索命中窗口、评价性措辞词表。两个角色选了同一个 agent 或同一个模型时，**只提示**"二次检查的独立性降低"，不阻止保存（用户决定，2026-11-09）。`review.ai` 不是 `all` 时，在复核员一栏提示复核员不能复核判断 | |
| D-26 | **测试连接**（新操作 `agent.test`，effect=user）分三步，逐步显示结果与耗时：① 命令能找到，`--version` 返回版本；② 用一句很短的提示启动一次，要求它通过 MCP 调用 `server_info` 并原样输出 actor；③ 核对输出的 actor 是这次测试运行的 `ai:…` 身份。测试输出保存在运行日志 | 能找到命令不等于 MCP 连得上、身份正确；测试会调用大模型，但这是人点的按钮 |

### 不外发标记

| 编号 | 决定 | 理由 |
|---|---|---|
| D-30 | **原件可以标为"不外发"**（用户决定设这个标记，2026-11-09）：新操作 `artifact.policy`（effect=user），记在账本新表 `artifact_policies`（只追加，按时间取最后一条，做法同 `retirements`） | 是人的决定，要留历史；不写回原件 |
| D-31 | **在巡检中的效果**：不外发的原件仍参与规则检查与覆盖图；巡检包里只列它的 ID、标题和规则检查结果，不含原文；巡检运行的会话里，`artifact_read` 读它被拒绝（`NOT_OUTBOUND`），`search` 不返回它的片段。涉及它的任务标为"只能人看" | 原文不经巡检发给云端 CLI |

## 4. 对不变式与影响表的影响

| 不变式 | 影响 |
|---|---|
| I1 账本只追加 | 新账本表 `artifact_policies` 加不可改触发器；人对发现的处理写 `reviews`；检索命中记在过程日志 `events` |
| I2 框架不能作依据 | 巡检发现、覆盖图都是框架；`basis_of` 拒绝 `fnd_`，发现与复核员的依据只能是原件层与判断层 |
| I3 可信度由系统推出 | 不变；发现与 AI 复核不改变判断的写入时可信度 |
| I4 调用者身份 | 新增系统身份 `system:inspection`（准备巡检包）；巡检员、复核员的身份照 agent 运行规则 |
| I5 只能由人做 | 新增 user 类操作：`agent.test`、`artifact.policy`、`inspection.import`、对发现的处理；开始巡检与交给复核员仍是 `agent.start` |
| I8 落盘格式只增不改 | 新表 `inspections`、`findings`（框架库）、`artifact_policies`（账本）；新 ID 前缀 `insp_`、`fnd_`；新事件 `search`；导出导入加入新表 |
| I12 只自动调用本地模型 | 不变；定时环节只用规则与本机向量模型，大模型都由人点按钮调用（D-01、D-02） |

模块影响表新增 INSP（`services/inspection.py`）与 COV（`services/coverage.py`）两行；改动 REV、AGT、RET、ART、OPS、WS、WEB、SKILL、STORE 各行的说明。

## 5. 不采用

| 方案 | 原因 |
|---|---|
| 按人建立的计划授权，定时自动调用巡检员（本稿讨论时的选项 B） | 要修订设计稿 05 §2 与 I12；用户选了定时准备、人点开跑（D-01） |
| 巡检员运行结束后自动启动复核员 | 同上，复核员也要由人发起（D-02） |
| 巡检发现写成判断（process 或 opposes） | 进入判断层后只能追加，误报撤不掉，还会混进检索结果；用户选了框架内容（D-16） |

| 以覆盖率作为首页指标或排序信号 | 会诱导为了覆盖率去读无关内容（原则 4）；与设计稿 06 D-19 对"热门即可信"的顾虑一致 |

## 9. 修订（2026-11-09）：巡检发现直接是一项待决策

用户在实现后提出：发现与待决策一一对应，单独的 `findings` 表和巡检页是重复的。决定（用户确认）：

| 编号 | 决定 | 理由 |
|---|---|---|
| D-32 | **每条巡检发现就是一项待决策**（`decisions.kind = 'finding'`，修订 D-16、D-23）：说明、依据、针对的条目、建议、任务、指纹、方式（ai / relayed）、复核员意见都在它的 `data` 里，`subject_id` 是第一个针对的条目；人的处理就是关闭它（采纳 → 已处理，驳回、忽略 → 已关闭，`resolution` 记动作与说明）。去掉 `findings`、`finding_reviews` 两张表与 `fnd_` 前缀（还没发版，迁移直接改）。待决策和巡检包一样存放在框架库，不能被引用（`basis_of` 把 `dec_` 当作框架拒绝） | 两套状态重复；待决策本来就不是证据 |
| D-33 | **提交发现时不再另开“请人复核”和可能矛盾边**（修订 D-18）：只开这一项。人认为要改时，从这一项打开针对的条目，用复核、更正、撤回或写反对判断 | 一条发现原来会开出两三项待决策，人要看几遍 |
| D-34 | **复核员对这一项交意见**：`review.ai_submit(item_id=dec_…)`（修订 D-20）；限制不变（先读后确认、不复核本会话提交的、经人转交的不能确认）。意见写进 `data.reviewer`，影响范围：确认 3、拿不准 1、不成立 0（折叠为低影响） | 与“请人复核”项附 AI 结论的做法一致 |
| D-35 | **不设巡检页**（修订 D-22）：待决策页顶部一个巡检栏（本期概况、准备、开始巡检 / 复制领取提示、离线包与贴回、关闭本期），下面是按巡检运行分组的待处理发现；首页提示链到待决策页。任务清单与往期列表不再显示；覆盖图页保留 | 巡检页上的内容大多与待决策重复 |

代价：发现的经过（提交、复核员意见、人的处理）记在这一项待决策的 `data` 里，待决策可以修改，不再是只追加的表；过程日志另有 `inspection.submit`、`inspection.ai_review`、`inspection.resolve` 事件。§8 实现修订 1（`finding_reviews`）由本节取代。

## 12. 收录原则与复核意见写入

按[公共记录原则](../../skills/RULES.md)取舍。连接测试、巡检和普通 agent 对话的输出留在运行日志。工作台启动时先登记巡检会话，外部客户端领取后登记。已识别的巡检会话禁止写判断和显式收录过程、原件或事实记录，内部审计照常留痕。

复核员确认发现后，可附核对过的依据提交拟写内容。意见仍在待决策中。人可以只采纳发现，也可以明确采纳并写入结论或追加更正。判断记录来源编号，引用复核员核对过的依据。见[开发历史 D-56](../DEVELOPMENT_HISTORY.md)。
