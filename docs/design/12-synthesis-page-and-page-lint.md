## 1. 背景（2026-11-13）

用户对照 Karpathy 的 LLM Wiki（见 `LLMWIKI.md`）检查综合页，提出：

1. 综合页要**尽量聚合信息、做信息导航**：非探索模式下用来快速复用当前经验，不需要特意避免框架污染；依据一定要落在判断层和原件层，但全文的撰写和思路不必如此。
2. 框架页的综合要像 LLM Wiki 那样**整体维护**。
3. 检索已经完整，导航不必再加一层；Lint 的要求写进巡检；Save 是否也是巡检的要求，需要分清。

### 1.1 现状（代码所得，2.1.5）

| LLM Wiki 的环节 | burrowl 现状 |
|---|---|
| Raw 不可变、Schema | 账本只追加；Skill 与 RULES |
| Ingest 触达多页 | 外部材料"消化"后并进综合页（设计稿 09），靠 AI 按 Skill 做；输入变化后页面标为 `inputs_changed` 并生成"需重新综合"待决策 |
| Query | `search` 的 `mode=reuse` 返回三列，`mode=explore` 不返回框架页；框架页按标题切成检索单元 |
| Confidence、Supersession | 依据构成 `basis_mix`、坐标、AI 复核、人复核；被替代的排在最后 |
| **Lint** | 巡检的检查项只针对判断、原件、规则与读取，**没有针对页面的检查** |
| **Save** | 判断层是对话结论的落点（`judgment_write`），巡检"经验未收录"兜底，但只看有操作日志的会话；**没有"判断已写、却没进任何页面"的兜底** |

## 2. 原则

1. **综合页是框架，永远不能作依据（I2 不变）。** 放宽的只是"写法"和"使用方式"，不是"能不能当依据"。
2. **不新增页面类型，不新增必须由 AI 持续维护的内容。** 导航靠检索、页内"相关"一节和关系图。
3. **巡检只准备、报告，不写入。** 页面体检和"判断未进综合页"都在本机按结构算出，不调用大模型；是否成立由巡检员读原件判断，处理由人。
4. **Save 的主路径在写入时，不在巡检。** 巡检是兜底。

## 3. 决定

### A. 综合页的定位

| 编号 | 决定 | 理由 |
|---|---|---|
| D-01 | **综合页的定位改为"聚合与导航的完整文档"**：围绕一个问题，把相关的判断、原件、尝试过的路线、对比、缺口聚在一页，并指向相关页面、实体和问题。草图 §11.3 的粒度、形态、结构不变；八项仍是"可以包含"（设计稿 09 D-13） | 用户定义：综合页要尽量聚合信息、做导航 |
| D-02 | **复用模式下不必刻意避开框架污染。** 综合页可以有归纳、组织、对比和"当前的理解"；`search` 的 `mode=reuse` 照常返回它，`mode=explore` 照常不返回（行为不变）。草图 §11.3 的"风险"改为：探索新路线时绕开它；复用时可以直接用，但只有判断和原件能当依据 | 用户决定；检索的两种模式本来就是为此设计的 |
| D-03 | **依据必须落在判断层和原件层，全文的写法不受限。** 页面里的每个结论性的句子应能经 `[[ID]]` 或 `inputs` 找到判断或原件；叙述、归纳、过渡的句子不要求有依据。系统在 `page_write` 时仍只检查输入存在（不变），"没有任何判断或原件作输入"由页面体检报出（D-07 a） | 不限制写法，只保证可追溯 |
| D-04 | **综合页要有摘要（`summary`）**，写成 1 到 3 句：这页回答什么问题、当前的结论、读者接下来该看哪里。摘要是它在检索里的入口。系统不因没写摘要拒绝写入，由页面体检报出（D-07 f） | 检索入口由综合页摘要承担（草图 §8"概览页"一行） |

### B. 导航不加一层

| 编号 | 决定 | 理由 |
|---|---|---|
| D-05 | **不设索引页、概览页、来源摘要页**（确认草图 §8）。"导航"由三样已有的东西承担：① 页内的"相关"一节，用 `[[pg_…]]`、`[[ent_…]]` 指向相关页面、实体和问题；② 关系图里的边；③ 检索结果带出的摘要。想看全貌时由关系图临时生成，不保存 | 检索已经完整；多一份会过时、会被误当依据的内容 |

### C. 页面体检（巡检检查项 `page_lint`）

| 编号 | 决定 | 理由 |
|---|---|---|
| D-06 | **新检查项 `page_lint`（页面体检）**：对每个未被驳回的综合页、实体页、概念页，在本机按下面 D-07 的规则算出问题；有问题的页生成一个任务，一页一个。**只看结构，不调用模型**。设置 `inspection.page_lint_max`（每期最多几页，默认 10，0 关闭），按问题数多、最近改动的在前 | 对应 LLM Wiki 的 Lint；巡检的既有位置 |
| D-07 | **体检规则**（`detail.problems` 里逐条给出，带编号方便界面分组）：<br>a. `no_basis`：输入清单里没有任何原件或判断（只有框架页或没有输入）；<br>b. `external_only`：输入的原件和判断里没有本地实证（`basis_mix` 的 `local` 与 `mixed` 都为 0，`external` 与 `inferred` 至少有一个）；<br>c. `lapsed_inputs`：输入里有已退役、已撤回、被替代（`current_ref`）或已删除的条目；<br>d. `stale_long`：停在"输入已变化"或"未核查"超过 `inspection.page_stale_days`（默认 14 天；自对应"需重新综合"待决策创建起算）；<br>e. `isolated`：不引用任何其他页面或实体，没有被其他页面的输入引用，图里也没有以它为端点的边；<br>f. `no_summary`：没有摘要（综合页）；<br>g. `overlap`：与另一页的输入重合度不低于 0.6（Jaccard，两页各不少于 3 个输入）——按草图 §11.3 "两页总在互相引用、一起被读时，就合并"提示合并候选（两页都要列出，只在编号小的一页生成，避免重复）。<br>规则只说"这里可疑"，不裁决 | 都能直接数出来，不判断"写得好不好" |
| D-08 | **任务的内容**：`targets` 是这个页面；`read` 取页面输入里最多 3 个带段落锚点的原件引用（计入阅读预算）；`question` 请巡检员用 `page_get` 读页面、读 `read` 里的段落，核对页面里的结论性句子是否如实反映依据、有没有与其他页面互相矛盾；`detail` 带问题列表、`basis_mix` 的一句话、输入数、重合页。巡检员的 `cites` 填页面输入里的判断，或自己读过的原件段落（框架页不能作依据，不变） | 语义检查（矛盾、不如实）交给读原件的巡检员；页面本身只当线索 |
| D-09 | **建议值**新增 `refresh_page`（重新综合该页）与 `merge_pages`（合并页面）。人采纳发现后，由 burrowl-consolidate 按这两个建议处理（D-13）；巡检员和复核员仍不写页面 | 巡检只报告，处理在框架维护的流程里 |

### D. 判断未进综合页（巡检检查项 `unpaged`）

| 编号 | 决定 | 理由 |
|---|---|---|
| D-10 | **新检查项 `unpaged`（判断未进综合页）**：本期范围内的结论和规定（不含过程），当前有效，且不在任何综合页、实体页、概念页的当前版输入清单里（引用的版本不限，按条目编号比对）。按第一个对象分组（没有对象的归为一组），一组一个任务；设置 `inspection.unpaged_max`（每期最多几组，默认 10，0 关闭），新的优先。**只看结构，不调用模型** | 这是 Save 的兜底：判断已写、页面没吸收。过程判断留在尝试过的路线一节，不算这一项 |
| D-11 | **任务的内容**：`targets` 是这组判断（最多 8 条）；`read` 取前两条判断引用的原件段落；`detail` 带对象、条数、**候选页面**（输入里有同一对象其他判断的页面，或主题是该对象的页面）；`question` 请巡检员判断这些结论应该并进哪一页、还是值得新写一页，或本来就不需要进页面（例行、单点结论）。建议值新增 `consolidate`（并进或新写综合页）；不需要进页面的交 `clear` | 不自动写页面，也不替人决定"要不要成页" |
| D-12 | **与"经验未收录"的分工**：`uncaptured` 管"有操作和产出、没有判断"（写入前）；`unpaged` 管"有判断、没有页面"（写入后）；两者都由人决定。**对话里得出、没有写成判断的结论**，系统看不到，只能靠 burrowl-work 的写入时义务（Skill 里强调"结论出来就写判断"）；巡检不承诺覆盖它 | 如实写出覆盖不到的部分 |

### E. 框架维护的衔接

| 编号 | 决定 | 理由 |
|---|---|---|
| D-13 | **burrowl-consolidate 增加"处理巡检发现"**：开头列出已采纳（`resolved`）、建议为 `refresh_page` / `merge_pages` / `consolidate` 的发现（`decision_list(status="resolved", kind="finding")`），按建议重综合、合并或新写页面，写完用 `page_write`；处理过的发现不再提出（指纹，设计稿 08 D-19）。综合页的写法补两点：写摘要（D-04）、写"相关"一节（D-05）；并写明复用模式下可以放心归纳（D-02） | Lint 只报告，不闭环就没用 |
| D-14 | **巡检原则（`DEFAULT_GUIDELINES`）与 burrowl-inspect 补写这两类任务的读法**；固定指令（`instructions()`）补一句：页面体检、判断未进综合页的发现里，页面只当线索 | 沿用现有结构 |
| D-15 | **前端**：检查项标签、设置页两个数值（`page_lint_max`、`unpaged_max`）加一个 `page_stale_days`、任务行里展示问题列表与候选页面、建议值标签 | 人要看得懂 |

## 4. 对不变式与影响表的影响

| 项 | 影响 |
|---|---|
| I2 框架不能作依据 | 不变；D-03 明确放宽的只是写法 |
| I5 只能由人做的操作 | 不变；巡检发现仍由人处理，新建议值不赋予 AI 写页面以外的权力 |
| I12 只自动调用本地模型 | 不变；两个检查项只读本机数据，`no_llm` 测试覆盖 |
| 影响表 INSP | 增加两个检查项与三个设置；"改动时一并检查"增加：页面体检的规则是否仍与 `basis_mix`、`ref_status`、传播的"需重新综合"待决策口径一致 |
| 不改表、不改格式号 | 旧巡检包没有新检查项时照常显示；`CHECK_LABEL` 取不到的旧值不会出现 |

## 5. 被放弃的方案

| 方案 | 为什么不用 |
|---|---|
| 维护一页 `index.md` 式的导航页 | 检索已经完整；草图 §8 已论证过 |
| 新增"页面 Lint"独立功能和独立待办 | 巡检已有"准备—领取—发现—复核—处理"的闭环，新检查项直接用它 |
| 巡检里自动重写页面 | 巡检会话不能写；重写属于框架维护，由 burrowl-consolidate 做 |
| 把 Save 整个放进巡检 | 巡检是事后、定期；对话结论要靠写入时的义务，巡检只能兜底已写的判断 |
| 用模型判断页面之间是否矛盾 | 定时准备不调用大模型（I12）；这一步交给读原件的巡检员 |
