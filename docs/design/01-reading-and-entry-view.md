## 1. 背景（2026-11-07 在 trial 数据目录上核对）

1. **原件页看不到原件**：条目页正文只有"标题 · 类型 · 保存方式 · sha256 · 时间"一行；工作台没有打开或下载原件的入口，只能到 `blobs/sha256/…` 手动复制。文本原件的分段已入索引，但页面不显示。
2. **原件与读取记录分成两类并列条目**：用户看到的是两个互不相干的页面。读取记录真正承担三件事：读过的证明、版本锚定、没用上的阅读；其中版本锚定判断引用本身就能承担（`art_…#seg-序号`，DESIGN 第 14 行；原件 ID 不可变，ID 即版本）。
3. **一次读取写两份**：`artifact_read` 同时写 `rd_` 读取记录和 `artifact.read` 过程日志。
4. **条目页的附属区难读**：① 把原始 JSON 直接铺开，标题不分类型；③"同一对象的其他记录"混着多个对象、最多 20 条截断、被自动的 `judgment.write` 日志填满；对象只显示 `ent_…` 编号。
5. **引用段落未加检查**：`basis_of` 接受 `art_…#seg-N`，但不检查段号是否存在，也不记下被引段落的指纹，版本传播只认读取记录里的 `segment_sha256`。

## 2. 决定

| 编号 | 决定 | 理由 |
|---|---|---|
| D-01 | **存储不合并，显示合并**：原件仍是原件，读取仍单独留痕；工作台以原件页为主页面，读取与引用显示成原件段落上的标记 | 合并存储会丢掉多次读取、读取粒度、版本对应，并让原件不再"原样"；用户要的是看一个地方 |
| D-02 | **判断依据的主路径是原件段落**：`cites` 推荐写 `art_…#seg-N`；写入时检查段号存在，并在判断里记下被引段落的 `sha256`（`cited_segments`），版本传播据此判断哪些判断受影响 | 段落引用自带版本（原件 ID 不可变），读取记录不再是锚定版本的必经之路 |
| D-03 | **读取记录降级为自动日志**：`artifact_read` 仍写 `rd_`（字段不变，账本只追加），但读取记录不再作为条目出现在条目列表、检索结果（包括 `mode=explore`）和建页门槛中；查读取情况一律从原件段落进入。去掉重复的 `artifact.read` 过程日志，只写 `rd_` | 读取是"读过"的证明，性质同过程日志，不需要用户逐条翻看；一次读取一份留痕 |
| D-04 | **旧引用兼容**：已引用 `rd_…` 的判断照常解析与传播；显示时折算为它所读的原件段落。新写入仍接受 `rd_…`，但 Skill 与 MCP 说明只推荐段落写法 | 账本只追加，旧判断不能改 |
| D-05 | **未读先引只提示**：结论或过程判断引用 `art_…#seg-N`，而该段没有同一 actor 会话内（无会话时同一 actor）的读取日志时，写入成功并在结果中返回 `warnings: [UNREAD_CITATION]`；可信度规则不变；工作台状态检查列出这类判断 | 检查保留"读过的证明"的价值；拒绝写入会妨碍人依据记忆或线下阅读写判断 |
| D-06 | **建页门槛去掉读取记录**：D-16 的计数改为原件、事实记录、判断（仍不含过程日志） | 读取已降级为日志 |
| D-07 | **原件文件接口**：新增只读接口按口令返回原件字节。受管原件从 `blobs/` 取；外部引用原件读登记路径，先核对指纹，不一致返回 `STALE_ARTIFACT` 并提示重新登记。按登记的文件名与类型设置 `Content-Type`；PDF、图片、文本内联显示，其余作为下载 | 用户要直接看原件；返回的必须是登记的那一版 |
| D-08 | **对象是条目的关联实体，可多个**：条目页不再列"同一对象的其他记录"，改为对象名称标签（名称 · 条数），点击进入对象页；对象页列出关于该对象的全部条目，约束与有争议的结论在前，其余按类型、时间；不显示自动的 `judgment.write` 日志，已提升为事实记录的过程日志只显示提升后的记录 | 条目页讲这一条，对象页讲这个东西 |
| D-09 | **附属区按类型命名并表格化**：原件的 ① 叫"来源"，过程日志与事实记录叫"条件"，键值对以表格显示；原始 JSON 收进"原始数据"开关；过程日志的输入、条件同样表格化，输出保留原样 | 默认只展示重要内容，原始数据随时可查 |
| D-10 | **抽取层属于原件，不是另一条原件**：每个原件最多一个当前抽取层，按"单元"组织（文本文件整份、PDF 的页、PPT 的页、图片整张、视频的时间段）；每个单元记文本、抽取方法、抽取者、时间、指纹、可信度档。抽取层不进条目列表；检索索引只由当前抽取层建立，命中显示为"原件 · 第 3 页 · 第 2 段"。账本只追加：抽取层每次变化写一条抽取记录（`ex_`，正文存 blobs），当前抽取层 = 每个单元最新的一条 | 两条记录并列让人分不清哪个是原件；每抽一部分建一条原件既难核对又会重复。原件字节始终原样，抽取单独留痕，抽错了只影响抽取层 |
| D-11 | **按格式决定默认抽取**：文本类（.txt .md .csv .json .py…）登记时自动整份复制；PDF 用 pypdfium2 自动抽每页文字层，没有文字的页标为"图片页，待抽取"；PPTX 用 python-pptx 自动抽每页的标题、正文、表格、备注；DOCX 用 python-docx 按文档顺序抽段落、标题、列表、表格；图片、视频、图片页默认不抽取，由人在工作台手动指定，或由 AI 明确调用 `artifact.extract`（`method=ai`）时进行。AI 抽取图片与图片页时，MCP 以图片形式提供原件页面（PDF 页由 pypdfium2 渲染）；视频由提交者给出带时间戳的转写，本程序不内置视频模型 | 图片和视频需要专业模型、消耗大，默认不做；常用的文字型格式本地即可可靠抽取 |
| D-12 | **抽取可信度分档**：`copy` 原样复制（文本类）> `parsed` 解析文字层（PDF 文字页、PPTX）> `ocr`（OCR 工具）> `ai` 模型识别（图片、图片页、视频转写）；任意档可被人确认为 `verified`（用户专属操作，工作台逐单元或整份确认）。引用 `ocr`/`ai` 档且未确认的单元时，写判断成功但返回 `warnings: [LOW_FIDELITY_CITATION]`，`artifact_read` 与检索结果同时带出档位和"请对照原件第 N 页复核"；判断自身的可信度规则不变 | 文字复制几乎不会错，模型识别会错；提示调用方回到原件核对，而不是把识别结果当原文 |
| D-13 | **抽取随时可重建，引用随之复核**：人或 AI 可对整份或指定单元重新抽取（换方法、换模型、补抽缺页）。单元文本指纹不变的，引用照常；变化或消失的，引用它的判断标为"依据抽取已变化，待复核"，状态检查列出；复核方式是重新读该单元后写确认或 opposes 判断（沿用现有机制，不改旧判断）。重复提交与当前相同的文本不写新记录 | 抽取可能变好也可能变坏，变化必须能追到受影响的判断 |
| D-14 | **段落定位按单元编号**：抽取单元内再分段，引用写成 `art_…#p3-2`（PDF/PPT 第 3 页第 2 段）、`art_…#img-1`（图片）、`art_…#av-4`（视频转写的第 4 段，段落带起始秒数）；文本类仍用 `art_…#seg-N`。补抽其他单元不改变已有编号 | 部分抽取、补抽是常态，编号不能因此移动 |
| D-16 | **抽取保留版式结构，不只是纯文本**：每个单元除了索引用的纯文本，还保存版式块列表（标题、段落、列表项、表格、图片、媒体；PPT 的块带位置与大小，DOCX 的块按文档顺序带标题级别、粗斜体、列表层级）。纯文本按阅读顺序由块生成，分段与块对应，引用高亮落在块上。嵌在 PPTX/DOCX 里的图片、视频取出为子单元（`#img-k`、`#media-k`），在原位置显示，默认不抽取 | 只存纯文本会丢掉"哪句在哪"，人对照原件时找不到位置 |
| D-17 | **页面快照保证"和原件一样"**：PPTX、DOCX 若本机装有 Microsoft Office 或 LibreOffice，在工作台首次打开该原件时（或手动"生成快照"、AI 调用 `artifact_snapshot` 时）在后台转成 PDF 存为快照（抽取记录的一种，方法记转换器与版本），逐页渲染为图像。工作台 PPT 每页默认显示快照图像，下方是可引用的文字块；DOCX 显示按版式块重建的正文，可切换到逐页快照。转换器顺序：Office → LibreOffice → 无；没有转换器时用版式块按位置重建（PPT）或按顺序重建（DOCX），并标"近似版式"。快照只用于显示，不进索引、不作引用对象 | 只有真正的排版引擎能保证与原件一致；文字层负责检索与引用，快照负责看起来一样，两者分开就不会互相拖累 |
| D-15 | **工作台默认显示抽取结果，并按格式优化**：显示什么与索引什么一致（都来自当前抽取层），原件随时可开。Markdown 渲染、CSV 表格、JSON 格式化、代码等宽；PDF 逐页显示文字，每页旁边"看原页"（内嵌浏览器 PDF 阅读器定位到该页），图片页显示页面图像；PPT 逐页卡片（标题、要点、表格、备注）；图片显示图像加识别文本；视频内嵌播放器加时间戳转写，点击跳转。每单元标出档位与是否已确认；未抽取的单元写"未抽取"并给出抽取按钮 | 工作台首先是给人读的，同一份内容不应要人在原件与派生文本之间来回找 |

### 实现修订（2026-11-07 开发时）

| 编号 | 修订 | 原因 |
|---|---|---|
| D-05 | 未读先引只对结论、过程提示；"读过"按同一 actor、同一会话（读取没有会话时按 actor）判断 | 规定不陈述世界，读没读过不影响它 |
| D-05 | 2026-11-15 修订（设计稿 14 D-01 至 D-06）：只查 AI 的引用；改版沿用的引用按最初写它的人算；同一 AI 别的会话读过也算；读的必须是被引的那一版；状态检查看先后 | 人只改标题时沿用的引用被记在人名下，造成误报；人在工作台读原件不留读取记录 |
| D-14 | 视频段落写 `av-N`，起始秒数放在段落里 | 转写可能补抽或重切，秒数做编号会和段号冲突 |
| D-17 | 快照不在登记时生成，改为首次查看、手动或 AI 调用时生成；转换期间放开数据目录的锁 | Office 转换要 5–20 秒，登记（尤其 MCP 调用）不应等它 |
| D-18 | 工作台新增"设置"页（每个数据目录的 `config.json`）：PDF / PPTX / DOCX 抽取 auto 或 off；图片、音视频只有"按需"；快照转换器 auto / office / libreoffice / none；多模态索引模型只有"无"（未实现） | 用户要求可选择抽取方式和索引方式 |
| D-19 | 整份重新抽取时，保留人工转写、OCR、AI 识别过的单元；内置抽取器读不出文字时也不覆盖它们 | 否则一次"重新抽取"会把人工转写改回"待抽取" |
| D-20 | 一个数据目录的全部操作在同一把锁里串行（`Workspace.lock`） | 原件页并行请求多，暴露了共用 SQLite 连接被打乱的问题（DEVELOPMENT_HISTORY D-21） |

## 3. 原件页的样子

```
[标题]  PDF · 受管保存 · 2026-11-05            [打开原件] [下载] [复制原路径]
正文
  ▸ 第 3 段（高亮）……原文……        被 2 次读取 · 被 1 条结论、1 条过程引用 ⌄
  ▸ 第 7 段（高亮）……原文……        被 1 次读取 · 未被引用
  展开全部 24 段
来源（表格）   对象：[设备 A · 12 条] [样品 B · 3 条]
```

PDF 原件（D-15）：

```
[Adam: A Method…]  PDF · 15 页 · 受管保存        [打开原件] [下载] [重新抽取 ▾]
抽取：第 1–15 页 · 解析文字层（pypdfium2 4.x）· 未确认            [确认整份]
  第 1 页  解析 ·  看原页 ↗
    ▸ 第 1 段 …文字…                     被 1 次读取 · 被 1 条结论引用 ⌄
  第 9 页  图片页 · 未抽取                [AI 抽取] [手动粘贴]
  第 10 页 AI 识别 · 未确认 ⚠ 引用前请对照原页
```

- 默认展开的"重要正文"：被引用过或被读过的段落（可客观计算）。
- 读取日志链接（来自旧引用或检查结果）直接定位到原件页对应段落并高亮，上方一行写读取人、时间、引用它的判断（按结论 / 过程 / 规定分组，没有则"未被引用"）。
- 旧数据中已登记为独立原件的派生文本（`metadata.derived_from`）：不导入（整份文本对不上 PDF 的页），两份原件的页面互相显示"派生自 / 旧的派生文本"；PDF 由补抽（`extraction.backfill`）得到自己的逐页抽取层；引用旧文本的判断照常有效。

## 4. 对不变式与影响表的影响

- 账本只追加不变：不删除、不改写已有 `rd_`；D-03 只改"哪些地方显示与计数"，以及新的读取不再写重复日志。抽取记录 `ex_` 同样只追加；原件字节与指纹不因抽取改变。
- 新依赖：`pypdfium2`（Apache-2.0/BSD，PDF 文字与页面渲染）、`python-pptx`（MIT）、`python-docx`（MIT）；均随安装包分发。Office / LibreOffice 是可选的外部程序，不打包，配置项 `snapshot.converter`（auto / office / libreoffice / none）。
- 框架不作依据不变；D-15 不变（过程判断仍不能作结论依据）。
- 需要更新：DESIGN（读取记录的地位、引用推荐写法）、CORE（读取流程、写判断流程）、ARCHITECTURE（影响表加原件文件接口、状态表）、GLOSSARY（读取记录、对象）、DEVELOPMENT_HISTORY（新增 D-19 起的决定，D-16 注明被修订）、README（工作台用法）、Skill 与 MCP 说明。
