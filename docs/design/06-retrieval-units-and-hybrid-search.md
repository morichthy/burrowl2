## 1. 背景（2026-11-08）

评测工作区 `D:/共享桌面/A_work/Burrowl-eval`（与产品代码分开，规则见其 AGENTS.md）的回归题 `regression-v1`：4 篇论文（Adam、Memory Tax、中文《光学锁相环的研究进展》、英文 Udem 2002），12 道典型问题题。2.0.0a12 的结果 B0：

| 指标 | B0 |
|---|---|
| 零命中 | 7/12 |
| 段落命中@10 | 4/12 |
| 条目命中@10 | 5/12 |

具体问题：

1. **整句查询零命中**：FTS5 trigram 要求每个词都命中；只要有一个词不足 3 个字，整条查询退回 LIKE，所有词都要出现。
2. **中文查英文（或反过来）零命中**：只有字面匹配。
3. **段落太碎**：4 篇论文共 2562 段，大量是标题、公式行、被分栏截断在句子中间的短行；`bias correction` 只返回 32 字的标题，正文段落被"每条目只留一段"挤掉。
4. **排序把相关度放在最后一级**：召回一杂，弱相关的本地原件压过强相关的判断。
5. **结果没有给 AI 继续查的线索**：同一条目里其他命中、判断的依据、引用它的判断都要另外去查。

文献依据（研究目录 FIELD-SURVEY §2、§15、§17）：Memory Tax 的增强型基础 RAG（自然边界块、BM25 + 向量取并集、重排、二轮）胜过多数记忆系统，块切得更细没有收益，最差的是不顾边界的固定窗口；A-RAG 给 agent 关键词、语义、读块三个粒度的工具，胜过 GraphRAG 和固定流程的 RAG；GraphRAG-Bench 显示图在简单事实题上更差。

## 2. 目标与非目标

**目标**：自然语言查询、跨语言查询能召回；命中落到可引用的段落；名次表示相关度，地位坐标照常给出并附说明；结果里带上继续查的线索；可选的联想模式。

**非目标**：服务端调用 LLM 抽取实体或改写查询（DESIGN §3.1）；按读取、引用次数加权（D-19，遗留）；多模态检索。

## 3. 决定

### 检索单元

| 编号 | 决定 | 理由 |
|---|---|---|
| D-01 | **检索单元与引用段落分开**。引用段落（`seg-N`、`p3-2`）不变，`SEGMENTER_VERSION` 不动；在它之上新增检索单元：同一份原件里相邻的段落顺序合并。命中先落到检索单元，再落回单元里最相关的段落（`cite_as`） | 段落编号被判断的 `cited_segments` 引用，不能变；碎段落上的 bm25 和向量都不准，跨段的答案也召回不全 |
| D-02 | **单元的长度按 token 估计**：中日韩字符按 0.9、其他字符按 0.25 估算 token，目标 300、上限 400。遇到标题就断开（标题作为下一单元的第一行）；单段超过上限时按句末标点切成几块，几块都指向这一段 | 链条里最短的模型是重排模型（512 token，含查询与上下文），单元不超过 400 就不会被截断；本机实测中文约 0.77–0.85 token/字 |
| D-03 | **单元断开的位置**：PDF 的页之间不断开（段落跨页很常见）；PPT 的幻灯片、图片、音视频的单元之间断开；Word 与文本文件按标题断开 | PDF 正文是连续的流；幻灯片之间通常无关 |
| D-04 | **机械上下文**：每个单元记"标题 › 各级小节标题"，由规则从抽取层的 `heading` 块（文本文件的 `#` 行）生成，单独存一列，参与检索与向量，不改段落正文和指纹；不用 AI 写的摘要 | AI 摘要是框架内容，进索引会造成框架污染；Memory Tax 的基线也给每块加了会话时间头 |
| D-05 | **其他条目**：判断、事实记录一条一个单元；框架页按 Markdown 标题切分；过程日志仍不进索引 | 判断很短；长框架页要能定位到节 |

### 召回通道

| 编号 | 决定 | 理由 |
|---|---|---|
| D-06 | **词法主路**：检索单元的文本按"中文双字滑窗 + 英文完整标识符与拆开的部件"预先切词（沿用旧版 `tokenize.py`，`TOKENIZER_VERSION`），存进 FTS5（unicode61）；查询切词后用 OR 连接，bm25 排序。原来的 trigram 段落表保留，作为短语路（整个查询作为短语出现时加入召回）和 `search_exact` 的基础。去掉"整条退回 LIKE" | OR + bm25 让部分命中也能召回，命中越多排得越前；双字让两个字的中文词可以命中 |
| D-07 | **向量路（可选）**：默认模型 jina-embeddings-v2-base-zh（中英双语，8192 位置，平均池化）。向量按"上下文 + 单元文本"的指纹和模型指纹缓存在 index.sqlite，重建索引不丢；编码超过 1024 token 的单元计数报告，不静默截断。后台补建，检索结果报告"已建 m / n"；没有模型或没建完时，词法路照常 | Memory Tax：混合检索比只用 BM25 高约 9 分；跨语言只能靠向量；双语效果由回归题的跨语言题衡量（遗留问题） |
| D-08 | **融合与重排**：各路（词法、短语、向量）在检索单元上用 RRF（k=60）合并，精确对象命中排最前；重排前 20 个检索单元（mmarco-mMiniLMv2-L12，多语言、int8），失败退回融合结果并在结果里写明。**修订（2026-11-08）：重排默认关闭**（`index.rerank=off`，可改为 `auto`）——回归题上加重排后段落命中从 8/12 降到 7/12，p50 从 58 ms 升到 1.9 s；它把图注、参数表排到回答问题的段落之前。等大评测或更好的重排模型再议 | 用户原先建议默认启用（前提是开销小、有帮助）；实测两个前提都不成立，见 §7 |

### 结果怎样排、怎样给

| 编号 | 决定 | 理由 |
|---|---|---|
| D-09 | **名次只表示相关度**（修订草图 §12.4 的"默认排序"）。每条结果照常带地位坐标，另加一行 `status_note` 说明。两条规则保留：相关对象的有效约束单列在最前（`constraints`）；已被替代、已退役的排在当前条目之后。`order="status"` 按原来的逐级规则排（工作台可选） | 由 AI 结合地位自己判断；两阶段排序的截断数 N 含义说不清；约束置顶是约束生效的机制（DESIGN §0），被替代的已不是当前主张 |
| D-10 | **按条目折叠**：同一条目的命中合成一条结果，带最多 3 个（默认，`retrieval.passages_shown`，D-21）命中的检索单元（每个有覆盖的段落、`read_as`、最相关段落的 `cite_as`、片段、上下文），`more_matches` 写还有几个命中单元没有展示，`size` 写条目有多少段、多少字 | 一份大 PDF 不再挤掉其他条目，也不丢失它自己的其他命中 |
| D-11 | **依据一并带回**（Memory Tax"让偏离可恢复"）：判断命中时附上它引用的原件段落或条目，框架页命中时附上输入清单，各最多 3 条（默认，`retrieval.basis_shown`，D-21），每条一句片段；读全文由 AI 决定 | 框架、判断是对原件的加工；把原件的引用和片段带回来，代价小，全文自动塞入会撑爆上下文 |
| D-12 | **一跳关系提示**（`relations`，不增加命中）：原件 → 引用它的判断、以它为输入的框架页；判断 → 它与其他判断的关系、它所在的框架页；框架页 → 输入清单（即 D-11）。探索模式下不给框架页，也不给"引用它的判断"（与 `entry_expand` 隐藏解读一致），过程内容按 `include_process` | AI 能顺着关系决定下一步查什么，而不用先猜 ID |
| D-13 | **读过的标记**：原件命中带 `read_before`（本会话读过其中的段落） | A-RAG 的读块工具对已读块直接提示，省去重复阅读 |
| D-14 | **结果顶部的 `hints` 与 `channels`**：例如"art_X 还有 7 个命中单元未展示"、"向量还没建完，结果只来自关键词"、"重排未启用：模型不在 …"、"命中的综合页是框架，不能作为依据，依据见 basis" | 让 AI 知道结果的局限 |

### 工具

| 编号 | 决定 | 理由 |
|---|---|---|
| D-15 | **`search_exact`**：字面查找（不分词、不排序），返回含有这段文字的段落及其 `cite_as`，按条目分组；遵守层、探索模式、过程内容、退役的过滤 | 设备编号、错误码、函数名、公式片段要逐字找；A-RAG 的关键词工具也是精确匹配 |
| D-16 | **`artifact_read` 支持段落范围**：`p3-8:p3-12`、`seg-3:seg-7`，检索结果的 `read_as` 直接给出这种写法 | 读一个检索单元覆盖的段落，不必读整页 |
| D-17 | **联想模式 `associate`**（不默认）：从检索命中（或给定的条目）出发走 1–2 跳，把检索没命中、但通过关系连着的条目加进来，每条带经过的路径 `via`，标为"联想"。可走的关系：判断之间的关系、判断对原件的引用、框架页的输入清单、实体提及与共享对象、AI 推断的边（相似、类比、可能矛盾，未被驳回），以及向量近邻。探索模式下只走判断层关系、引用、共享对象和向量近邻 | 默认的关系提示（D-12）只注释已有命中；联想是扩大召回，会带来噪声，所以单独一个工具并标明来源。不在导入时由服务端抽取实体图：现有关系都是使用时写下的显式关系或按规则建立的关系，实体抽取仍交给 agent |
| D-18 | **Skill 写明检索策略**：工具怎样选、关键词与自然语言并用、原件是英文时也用英文查、名次只代表相关度、怎样用 `basis` / `relations` / `more_matches` / `read_as`、查不到就换说法再查一次、什么时候用联想、探索模式的限制 | 检索效果很大程度取决于 agent 怎样用工具 |

### 参数

| 编号 | 决定 | 理由 |
|---|---|---|
| D-21 | **数量类检索参数可在设置里调整（2026-11-09）**：每条展示的命中单元数、片段长度、依据与一跳关系的条数、省略 `limit` 时的返回条数（检索 20、字面查找 50）、重排候选数、RRF 常数、候选池（`max(下限, limit × 倍数)`）、短语路上限、联想的起点数 / 展开上限 / 向量近邻阈值，放在数据目录 `config.json` 的 `retrieval` 组（默认值 `services/retrieval.py` 的 `RETRIEVAL_DEFAULTS`，范围 `ops.SETTING_NUMBERS`，超出拒绝）。**工作台与 AI 读同一份**：MCP 进程每次取数据目录时核对 `config.json` 的修改时间，被别的进程改过就重读（`Workspace.refresh_config`），不用重启客户端；`search` / `search_associate` 的结果带 `params`，写明本次用的值，Skill 不写死数字。只有人能改（`settings.set` 是 user 操作），每次修改记一条过程日志 `settings.set`（旧值、新值，密钥不记原文）。只影响查询，不用重建索引；回归题按默认值评测 | 用户希望这些参数可以调，而且调了以后 AI 的行为跟着变、和工作台对得上。没有放开的：分段与检索单元的长度（改了要重建索引，见 D-22）、各类关系的联想权重、补建与重排的批大小（只影响速度和内存）、版本号；探索模式不给框架页、被替代的排后等是设计规则，不是参数 |

| D-22 | **检索单元的长度可在设置里调整（2026-11-09）**：目标长度、上限（token 估计）、机械上下文字数放在 `config.json` 的 `index.units_target` / `units_max` / `units_context_chars`（默认 300 / 400 / 160）。检索单元是索引里的派生物，段落编号和引用不变；改了就由保存设置的进程在**后台**整库重建索引（`Workspace.start_rebuild`：逐条取锁、不先清空，旧索引行逐条被替换，期间其他请求照常；重建中设置又变了就再来一遍；`settings.set` 立即返回 `rebuild` 状态），向量按新单元的内容在后台重算。首页"状态"卡显示重建进度（`index.health` 的 `units`）和向量已建 m / n；重建中、向量补建中是蓝色呼吸灯，全部就绪才是绿灯（H-21）。**修订（2026-11-09）**：最初是在保存设置的请求里同步重建，持有数据目录的锁，首页的请求全部排队，见 DEVELOPMENT_HISTORY H-20。非默认的长度写进索引版本（`Workspace.index_version`，默认值不写，已有数据目录升级时不重建）；别的进程发现索引版本与自己读到的配置不一致时，检索结果提示"正在重建、可能不全"，不自己再重建一遍。校验：目标长度不超过上限；打开重排时上限不超过 400、上下文不超过 160 字（重排模型输入 512 token，含查询与上下文）。**分段的 `segment.MAX_CHARS`（1500 字）不放开**：文本原件的 `seg-N` 每次按它现算，改了会让已有判断的引用对不上（I8） | 单元长短影响定位精度与上下文完整度，值得按语料调；重建索引是允许的（I9），改引用编号不允许 |
| D-23 | **数值设置先改后存（2026-11-09）**：设置页的检索参数与检索单元长度只改草稿，页面底部列出"旧值 → 新值"和关键影响（是否重建索引与重算向量、新目标长度约合多少汉字、AI 每次检索最多读进多少字的片段、召回与融合参数会改变名次、是否偏离评测用的默认值），范围与跨项校验不通过时不能保存；确认后一次保存。**扩展（2026-11-09）**：设置页所有下拉选项（抽取方式、页面快照、默认阅读器、模型与引擎、AI 复核、向量模型、重排）也走同一个待保存栏，各自写明影响（例如 PDF 改 MinerU 分段会改没被引用的原件的段落编号、版面引擎"整份替换"会让引用的判断进入待复核、大模型地址不是本机时原件截图会发出去、换向量模型要重算全部向量）；跨项校验看草稿后的值（例如草稿里同时打开重排、加大单元上限）。地址、密钥、启动命令仍用各自的"保存"和"测试连接"按钮 | 用户反馈改一个数字就立即生效、触发重建，没有机会看清后果；随后要求全部设置统一 |

## 4. 对不变式与影响表的影响

- I9（索引可删除重建，不返回旧版本）：检索单元同样记条目与版本；框架页的旧版本单元不返回。向量是按内容指纹的缓存，`index.clear` 不删，内容变了自然不再被用到。
- 段落编号与指纹不变（D-01），已有判断的引用不受影响；回归测试检查重建后 `cited_segments` 仍全部对上。
- 新依赖：onnxruntime、tokenizers、numpy（进入安装包）。模型不进安装包，放在 `<Root>/models/`（`BURROWL_MODELS_DIR` 可改）。
- 不碰账本：只新增 index 库的迁移 `0002`。
- 新配置：`index.embedding_model`（`jina-v2-base-zh` / `none`）、`index.rerank`（`auto` / `off`），只有人能改。
- 新配置组 `retrieval`（D-21）：旧 `config.json` 没有这一组时取默认值；只影响查询。
- 新配置 `index.units_*`（D-22）：取默认值时索引版本不变；改了就重建索引（I9 允许），段落编号与引用不变（I8）。
