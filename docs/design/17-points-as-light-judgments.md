## 1. 背景（2026-11-16）

设计稿 16 让要点照搬判断的写法后，用户指出定位本身有问题：

| 问题 | 原因 |
|---|---|
| 要点像是"只能从一份原件抽"的摘录 | 依据只能是原件段落；消化流程一份材料一批；定义是"外部材料里的一个论断" |
| 要点之间、要点到综合页没有关系 | 框架边技术上能连要点，但 Skill 没教、关系图不显示；综合页不以要点为输入 |
| 约束太重 | 设计稿 16 把判断的三条规则（定义引用原文、条件只写原文给出的）整套搬给了要点；对导航与复用的条目过重 |
| 噪声 | "一个论断一条、不设上限"：一篇论文 13 条，五十篇几百条；不去重、不合并、不淘汰 |

用户的定位：要点应当是以经验复用和快速导航为原则、框架污染等约束放轻的判断，是关系图（原件 → 要点 → 框架页、要点之间）的重要部分；同时要让显示不乱、控制噪声。

## 2. 决定

### A 定位

| 编号 | 决定 |
|---|---|
| D-01 | **要点是轻判断**：与判断同一种论断结构（设计稿 16 D-01），为**经验复用、快速导航、联想**而写；放在框架层，**不能作为依据**（唯一的硬界线；越过它要点就要回到判断层的全部约束）。可以概括、可以跨来源、可以带推测（写明是推测） |
| D-02 | 要点带标签 `subkind`：`digest` 摘要（一份材料说了什么，默认）/ `lesson` 经验（从几处材料或几条判断归纳出的、可复用的规律或做法）。经验只引用一处来源时给提示 `LESSON_SINGLE_SOURCE` |
| D-03 | **来源放开**：`cites` 可以是原件段落、原件、事实记录、判断，也可以是别的要点；可以跨多份材料。至少一项引用（出处可回溯）。去掉"至少一项直接依据"的硬要求。引用固定到当时的版本 |
| D-04 | **写法只硬性要求两条**：有出处（至少一项引用）、单独读得懂（标题写出对象）。其余都是提示：`CONTEXT_DEPENDENT`、`DEFINITION_UNCITED`；`CONDITIONS_UNSTATED` 只对摘要提示（转述材料要写原文给出的条件）。设计稿 16 D-05 对要点的"三条规则全部适用"改为"判断的规则可参照，不强制" |
| D-05 | 要点需要当依据时，**升级为判断**：读原件段落、按判断的规则另写一条判断（不引用要点）；要点可以留着做导航 |

### B 关系

| 编号 | 决定 |
|---|---|
| D-06 | 要点之间、要点与别的条目之间的关系用框架边，词表收为一小组：`may_support` 一致、`may_contradict` 矛盾、`refines` 细化（本条是对方的具体化或下位）、`related` 相关（另有 `similar`、`analogy` 照旧可用）。新增谓词 `refines` |
| D-07 | `point_write` 增加 `links: [{rel, target, why}]`，写入时一并建这些边（主语是本条要点）。框架边不算依据，不进坐标推出 |
| D-08 | 综合页以要点为主要输入：原件 → 要点 → 综合页。Skill burrowl-consolidate 写明先用要点、再回原件或判断核对 |

### C 噪声：写入、存在之后、显示

| 编号 | 决定 |
|---|---|
| D-09 | **先查后写**：写入时返回最相似的几条现有要点（`similar`，按检索打分），相似度高时给提示 `SIMILAR_POINT`。说的是同一件事时把新来源**并进已有要点**：`point_write(revises=…, add_cites=[…])`，正文不改也可以 |
| D-10 | 改写权限放宽到"框架可由 AI 维护"：AI 可以改写 AI 写的、人还没复核过的要点（不限本会话）；人复核过的只有人能改。改写后复核回到"AI 生成" |
| D-11 | **归档**（`point_archive`）：归档的要点默认不出现在检索、关系图、列表、首页计数里，可以恢复（`point_restore`，人）。AI 只能在**合并**时归档（给出 `merged_into`，且被归档的是 AI 写的、人没复核过的）；其余归档由人做（巡检提议）。归档记在页面数据里，不删版本 |
| D-12 | **活跃度**（读取时算，不存）：被检索返回的次数（窗口内，`events` 里 `search` 的命中）、作为综合页输入的次数、框架边数、来源数。`point_get` 与检索结果带 `use` |
| D-13 | 巡检两项新检查：**闲置要点** `point_idle`（写入超过 `point_idle_days` 天、窗口内没被检索返回、不是任何页面的输入、没有框架边）→ 建议归档或合并；**重复要点** `point_dup`（两条要点的文字高度相似且没有连边）→ 建议合并（`merge_points`）。上限 `point_lint_max` |
| D-14 | Skill：一份材料通常 3–7 条，只写**会有人回来找**的（结论、可复用的做法、适用范围与局限），背景和铺垫不写；去掉"一个论断一条、不设上限"。写之前先检索，能并进已有要点就并 |
| D-15 | **检索**：要点在一次检索里最多返回 `retrieval.points_max` 条（默认 5，超出的按名次截掉）；归档的不返回 |
| D-16 | **关系图**：泳道按抽象程度从左到右：原件 → 判断 → 要点 → 框架页与对象。默认只单独画"有关系的要点"（有框架边、或是页面的输入）；其余按第一来源原件折叠成"要点 ×N"（设计稿 16 D-13 的折叠，阈值降为 2）。归档的不画 |
| D-17 | 要点页显示标签（摘要 / 经验）、活跃度、关联（框架边）、被哪些综合页用到、归档说明；框架页列表的归档要点默认不列，可以切换查看。关系图里经验类要点加粗描边 |
| D-18 | 传播：要点引用的原件只在原件本身变化时影响它（设计稿 15 D-34 不变）；引用的判断、事实记录、要点变化时照常传播 |
