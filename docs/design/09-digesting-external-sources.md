## 1. 背景（2026-11-12）

入库的文献和外部材料没有被充分利用。对照 Karpathy 的 LLM Wiki（原始材料不可变；摄取时把一份来源编译进 10 到 15 个页面；定期 Lint 找矛盾、过时说法与缺口），burrowl 已有不可变的原件、段落级出处、带输入清单的综合页和"输入已变化"传播，缺的是**摄取**这一步：

| 问题 | 现在为什么会这样 |
|---|---|
| 文献里的发现不会变成可检索、可引用的判断 | 草图 §12.2 规定导入时不写判断，判断等"实际用到时"才写；`judgment_write` 虽有 `external_author`，却没有流程驱动它 |
| 文献的内容进不了综合页 | 综合页只能引用判断和原件，而没人从文献里提取论断 |
| AI 不知道一条判断该信几分、要不要回原文、要不要本地验证 | 检索结果有地位坐标，Skill 只说"名次不等于可信"，没说按地位怎么用 |
| 文献给的条件常常不全 | 写入时没有任何提示，用的人以为条件齐全 |
| 正文里的引用是完整条目名，打断阅读 | `[[ID]]` 渲染成"类型前缀 + 标题或短句"（开发历史 D-64） |
| 关系图只能按节点类型和关系类别筛选 | 没有按依据来源筛选，也没有常用组合 |

## 2. 原则

1. **文献论断地位高于框架、低于本地实证**：它有出处、能作为依据、不随框架重写而变；但依据来源是外部报告，永远不能称为"我们验证过的"。
2. **地位靠坐标区分，不靠放在哪一层区分**：判断层保证的是"出处如实"（当时谁、依据什么、认为了什么），不保证内容为真（[术语表](../GLOSSARY.md)"判断"）。可靠程度由依据来源 × 综合程度两个轴表达（草图 §12.4）。
3. **提取不引入框架性影响**：只转述原文自己的发现，不评价、不归纳、不补条件。
4. **给人看的要好读，给 AI 的要找得到**：综合页正文是自然的文字；来源与风险的细节由系统算出、由检索结果带出，规则写在 Skill 里。
5. **调用边界不变**：工作台不自动调用大模型；从工作台发起的消化由人点按钮。

## 3. 决定

### 文献论断的地位

| 编号 | 决定 | 理由 |
|---|---|---|
| D-01 | **外部材料的论断写成判断**（`kind=conclusion`，不新增判断类型）。修订草图 §12.2：外部原件（`source_class=external`）登记后要经过一次"消化"（D-04 至 D-09），把其中的论断写成判断；本地实证与推断类原件仍按原规则，在实际使用时才写判断 | 类型回答"这是什么话"，依据来源回答"凭什么"，两个轴独立。新增"文献论断"类型会把两轴混在一起：厂商手册的"最高 80°C"是规定还是文献论断？一半依据来自文献的结论归哪类？被本地验证后要改类型吗（账本改不了）？ |
| D-02 | **"文献论断"是系统推出的显示标签**：判断带 `external_author`，或当前依据全部是外部报告（不含本地实证），就标为"文献论断"。不落盘新字段，从写入时可信度与复核补充的依据算出。工作台、检索结果的 `status_note`、关系图节点都显示 | 让人和 AI 一眼区分，又不改落盘格式（I8） |
| D-03 | **检索加来源筛选** `source`：`all`（默认）/ `local`（只要依据全部为本地实证的判断、本地实证原件，以及规定）/ `external` / `inferred`（含该来源即返回）。`search`、`search_associate`、`entries.list` 共用 | 需要"完全可靠"的视图时直接取 `local`，判断层本身不必拆开 |

### 消化：从外部材料提取论断

| 编号   | 决定                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | 理由                                               |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| D-04 | **两个入口**：① AI 在平时会话里用 `artifact_register` 登记外部材料后，按 Skill 当场消化（调用大模型的是 AI 客户端本身，不是工作台）；② 从工作台导入、或 AI 没来得及消化的，进入"待消化"清单，人在首页或原件页点"交给 AI 消化"，用设置里的 agent 走 `agent.start`（发起人记为人），也可以"复制提示"交给任何连了 burrowl MCP 的客户端                                                                                                                                                                                                                                                                                                                | 约束 7 / I12：工作台不自动调用大模型。做法与巡检相同（设计稿 08 D-01、D-27） |
| D-05 | **消化记录**：新操作 `digest.submit(artifact_id, claims, note)`（effect=write）在过程日志里记一条 `digest` 事件（系统流水，加入 `INTERNAL_OPS`），列出这次写的论断判断。系统核对 `claims` 都是本会话写的、引用了这份原件的判断。零条论断时 `note` 必填（例如"综述，没有自己的发现"）                                                                                                                                                                                                                                                                                                                                 | 有记录才能算出"已消化"，也能追溯哪次消化写了什么                        |
| D-06 | **待消化由系统算出**，不单独存储：外部原件的当前版本没有 `digest` 事件、也没有被人跳过，就是待消化。人可以"不需要消化"（`digest.skip`，effect=user，同样记一条 `digest` 事件，`skipped=true`）。新版本（`version_of`）重新算                                                                                                                                                                                                                                                                                                                                                                           | 状态可再生；跳过是人的决定，要留痕                                |
| D-07 | **提取规则**（写进 Skill burrowl-work 的"消化外部材料"一节）：<br>1. 只收这份材料**自己的**发现、结果、适用范围和局限；转述别人的内容不收，需要时去登记原始文献。<br>2. 逐条忠实转述，`cites` 精确到段落，先 `artifact_read` 读过。<br>3. 不加评价和框架性措辞（"显然""这说明""关键在于"），不把几篇文献合成一条，不加入自己的推论；推论另写，依据是这些论断。<br>4. `external_author` 写原作者（如"Kingma & Ba, 2015"），`objects` 写涉及的对象。<br>5. 每份材料论断数有上限（设置 `digest.max_claims`，默认 12），优先收和已有对象、问题相关的。<br>6. 写之前先 `search` 去重；与已有判断有关的用 `relations` 连上（`supports`、`opposes`、`coexists_under`）。<br>7. 消化完更新相关的综合页、实体页、概念页（按 burrowl-consolidate 的门槛），最后调用 `digest.submit` | 防止确认偏差和摘要化丢失条件（LLM Wiki 的主要风险）；上限控制噪声            |
| D-08 | **条件不全的提示，放在三处**：<br>① 提取规则：`conditions` 只写原文给出的条件，原文没说明的不补、不猜，写成"原文未说明：……"。<br>② 写入时：判断带 `external_author` 而 `conditions` 为空时，写入照常成功，返回提示 `CONDITIONS_UNSTATED`。<br>③ 使用时：检索结果的 `status_note` 对这类判断加一句"条件未说明"；burrowl-read 写明"外部论断条件不全是常态，使用前对照自己的条件"                                                                                                                                                                                                                                                                         | 文献和报告很少给出完整条件；在写入、检索、使用三处各提醒一次，比只写在一处可靠，又不阻断写入   |
| D-09 | **不建文献页**：论断按主题并进综合页、实体页和概念页。一份原件提取了哪些论断，在原件页"从这份原件提取的论断"一栏列出（引用它、带 `external_author` 的判断，由系统列出）                                                                                                                                                                                                                                                                                                                                                                                                                               | 同一主题的文献与本地实证放在一页才方便对比；单独的文献页会和综合页重复、不同步          |

### 按地位使用判断（Skill 与提示）

| 编号 | 决定 | 理由 |
|---|---|---|
| D-10 | **按地位决定怎么用**，写进 RULES（公共规则）与 burrowl-read：<br>1. 依据全部为本地实证、或人已复核：可以直接用。<br>2. 外部报告（同行评议）：可以用，说明来源；条件要对照自己的情况。<br>3. 预印本、厂商资料、网页、单一来源、AI 推断未复核、条件未说明、依据已变化：当作线索。<br>4. **回原文**：结论要用于动手、决策，或要写成新结论的依据时，凡是第 3 类，先 `artifact_read` 读原文核对条件。<br>5. **本地实证**：结论要用于动手或决策，而依据只有外部报告或推断，并且本地能做时，建议用户安排本地验证；做了就用 `capture_log` 留痕，写本地结论，用 `supports` 或 `opposes` 连到原论断。<br>6. 外部论断与本地实证冲突：写 `opposes` 留下记录，不删除、不忽略；当前做法以本地实证为准，并说明条件差异 | 让 AI 按情况决定信几分、要不要回原文、要不要本地验证 |
| D-11 | **MCP instructions 加一句**：依据只有外部报告或推断、而结论重要时，先回原文核对；文献条件常不全 | instructions 对所有客户端生效，包括没加载 Skill 的客户端 |
| D-12 | **页面的依据构成由系统算出**：`page_get` 与检索结果中的框架页带 `basis_mix`，例如"本地实证 3、外部报告 5（其中只有外部依据的结论 2）、推断 1"，从输入清单算出，不写进正文 | 数字由系统算，不会写错，也不占正文 |

### 综合页与引用的显示

| 编号 | 决定 | 理由 |
|---|---|---|
| D-13 | **综合页可读优先**（修订 burrowl-consolidate"综合页的结构"）：用自然的段落写，原来的八项是"可以包含"，不是固定栏目；不加可信度表，不按来源分组。只有外部依据的重要结论，在句子里注一句"（文献报告，尚未本地验证）"；风险的细节交给 D-12 和检索结果 | 人要读得下去；AI 有 D-10 至 D-12 就能找到来源与风险 |
| D-14 | **正文引用显示为上标**：判断、框架页、事实记录等所有用 Markdown 显示的正文里，`[[ID]]` 显示为上标编号；同一条目在一篇正文里共用一个编号。悬停显示卡片（条目名、列与类型、依据来源、复核状态与警告；原件段落另有"阅读"入口）；点击跳到正文底部的"引用"列表（完整条目名与链接）。`cites`、关系等字段列表照旧显示名字；MCP 返回的正文仍是 `[[ID]]` | 长条目名打断阅读；论文式引用是人熟悉的读法 |

### 关系图

| 编号 | 决定 | 理由 |
|---|---|---|
| D-15 | **按两轴筛选节点**：综合程度（原件 / 判断 / 框架）与依据来源（本地实证 / 外部报告 / 推断）。原件按 `source_class`，判断按当前依据（混合来源的含其中任一即匹配），框架节点不参与来源筛选。判断另可按类型（结论 / 过程 / 规定）和"文献论断"筛选。`graph.view` 新增参数 `layers`、`source_classes`、`judgment_kinds`，在服务端先筛后裁剪 | 节点已带坐标；先筛后裁剪才不会被 300 个节点的上限截掉要看的部分 |
| D-16 | **常用组合**（筛选栏顶部的单选按钮，改动任一筛选后显示为"自定义"）：<br>1. **默认**：全部节点、全部关系（现状）。<br>2. **探索**：只保留原件与不带框架倾向的判断：去掉框架页、实体节点、过程判断，关系只留依据、支持、冲突、替代；与 `search(mode="explore")` 一致。<br>3. **只看本地实证**：本地实证原件、依据全部为本地实证的判断、规定。<br>4. **文献对照**：外部原件、文献论断，以及与它们有支持或冲突关系的判断。<br>5. **证据链**：原件、事实记录、判断，关系只留依据、支持、冲突、替代，隐藏已被替代的 | 用户要求提供常用组合；"探索"与检索的探索模式口径一致，避免被已有思路和框架带偏 |

## 4. 对不变式与影响表的影响

| 不变式 | 影响 |
|---|---|
| I1 账本只追加 | 不变；消化写的是普通判断与过程日志 |
| I2 框架不能作为依据 | 不变；`basis_mix`、组合筛选、引用卡片都是框架内容 |
| I3 可信度由系统推出 | 不变；"文献论断"标签和 `basis_mix` 从可信度算出，AI 不能声明 |
| I5 人才能做的事 | 不变；跳过消化（`digest.skip`）、启动消化 agent、采纳复核意见都只能由人做 |
| I8 落盘格式只增不改 | 新增：过程日志操作 `digest`、设置 `digest.max_claims`、待决策 `data.reviewer.proposed_kind`；不改已有字段 |
| I11 过程内容不能作为结论的依据 | 不变；"探索"组合去掉过程判断 |
| I12 只自动调用本地模型 | 不变；待消化清单由系统在本机算出，消化由 AI 会话自己做或由人点按钮启动 |

修订的文档：草图 §12.2（外部材料要消化）、Skill burrowl-consolidate（综合页结构改为可选项）。

## 5. 不采用

| 方案 | 不采用的原因 |
|---|---|
| 新增判断类型"文献论断"（`reported`） | 与依据来源轴重复，规定、混合依据、被本地验证后的归类都说不清（D-01） |
| 文献论断放进框架层 | 框架可以重写、不能作为依据；文献论断有原件出处，地位应高于框架 |
| 每份文献建一页"文献页" | 与按主题的综合页重复、不同步（D-09） |
| 综合页按本地实证 / 外部报告 / 推断分组，或附可信度表 | 太琐碎，影响阅读（D-13） |
| 登记外部原件后由工作台自动调用大模型消化 | 违反约束 7 / I12（D-04） |
| 由巡检员顺便消化 | 巡检会话不能写判断（D-17） |
| 条件不全时拒绝写入 | 文献条件不全是常态，拒绝会让论断写不进来；改为提示（D-08） |

## 6. 未决

1. `digest.max_claims` 的默认值（暂定 12）要在真实文献上试过再定。
2. 推断类导入材料（例如外部的讨论记录）要不要也走消化。暂定不走，按原规则在使用时写判断。
3. 关系图的"自定义"组合要不要可以保存。暂定不保存，只保留当前视图。
4. 消化 agent 是否与巡检员共用 agent 配置。暂定在设置的「Agent」里另选一条。
