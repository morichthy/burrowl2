## 1. 背景（2026-11-16）

trial23 按设计稿 15 处理完后，用户在工作台上看到三个问题：

| 观察 | 原因 |
|---|---|
| 判断引用一份原件的多个段落时，依据栏每段一张卡，同一份原件占好几张，很乱；但能看出每个编号引了哪段，这一点有用 | 关系区按关系逐条画卡（设计稿 10 D-27），没有按原件归并 |
| 要点没有出现在关系图里 | 关系图默认的节点类型不含要点（只在以原件为中心时自动带上），设计稿 15 §8 的"按原件折叠"没做 |
| 要点"没头没脑"：如"ε=0 时 Adam 每步的有效步长约不超过 α"，正文直接用 m̂_t、v̂_t、ζ，不说是什么 | 要点只要求"写法同转述的结论"，但写判断的三条规则（尤其规则 2：对象全称、专有量展开并引用定义、不用依赖上下文的说法）没有对要点明说；系统对要点也只检查条件，不检查定义 |

用户要求：要点的形态和结构与判断一致，用同一个基础管理；参考判断对定义和上下文的要求，看要点有没有必要这么写。结论是有必要：要点会被检索、联想整条返回给 AI，单独读不懂就失去导航作用。

## 2. 决定

| 编号 | 决定 |
|---|---|
| D-01 | **判断与要点是同一种论断**。结构相同：一句话 `title`、正文 `text`（行内引用 `[^n]`）、依据 `cites`（每项 `{ref, marker, role, why}`）、条件 `conditions`（可带 `scope_unclear`）、对象 `objects`、原作者 `external_author`。区别只在所在的列：判断存在只追加的账本，另有类型、标签、立场关系、本地实证、重开条件，能作为依据；要点存成框架页，`cites` 只能是原件段落、至少一项"直接依据"，不能作为依据 |
| D-02 | 共同底子放在 `services/claims.py`（`ClaimService`，`ws.claims`）：`prepare`（整批校验依据与关系、`[^n]` 与 marker 一一对上，原 `judgments._prepare`）、`notices` 与 `notice_warnings`（依据提示，原 `judgments._notices` 与 `_finish` 里的提示文字）、`lint`（写法检查）。`judgments` 与 `framework.point_write` 都调用它；存储不合并——合并会让框架条目进入账本，违反 I2 |
| D-03 | 要点增加 `scope_unclear`（与判断同义：原文适用范围不清楚但仍值得留下），设了就不报"没写条件"，说明里显示"适用范围未明"。落盘只是页面版本 `data` 多一个字段，旧数据照常读 |
| D-04 | **写法检查（`ClaimService.lint`）判断与要点相同**，只提示、不拒绝：`FRAMEWORK_WORDING` 框架性措辞；`CONDITIONS_UNSTATED` 结论与要点没写条件（`scope_unclear` 时不报；转述的用"只写原文给出的条件"那句）；`DEFINITION_UNCITED` 正文有符号或专有量记号（带下标、上标、帽子的记号，希腊字母）却没有一项依据的 `role` 是"定义"；`CONTEXT_DEPENDENT` 出现「如上」「同前」「上述」「本次」「该方法」「本文」「作者指出」这类依赖上下文的说法。只按字面，不调用模型；查不出"术语没展开"这类语义问题，这部分留给巡检员与复核员 |
| D-05 | RULES §1 改写要点一段：要点与判断同一种论断，§3 三条规则同样适用；"凝练是去掉铺垫，不是去掉上下文"；标题写出对象和论断；第一次出现的符号用文字说明并引用定义；实验类论断写出数据集、指标、比较的方法与设置。附两组反例与正例（来自 trial23 的 Adam 要点） |
| D-06 | Skill burrowl-work 的消化步骤：写要点按 RULES 的三条规则；每条写完看 `warnings`，有写法提示时用 `revises` 改写 |
| D-07 | 巡检的要点体检加上写法检查的结果（`no_definition`、`context_dependent`、`framework_wording`），与写入时的提示一致 |
| D-08 | MCP `point_write` 的参数说明改成与判断相同的写法要求，并加 `scope_unclear` |
| D-09 | **抽取变化传到要点**：原件重新抽取后，所引段落的指纹已不在当前抽取里的要点（当前版）标为"输入已变化"并生成待重新综合项（`propagation.mark_pages`）。只看指纹变了的段落，同一原件别的段落变化不影响 |
| D-10 | **跨来源可能矛盾**（巡检检查 `point_conflict`）：要点与另一来源（不同原件的要点、引用别的原件的结论）对象相同、字面上相反或数值不同（沿用疑似冲突的 `opposite`），又没有建立关系时，列为候选。已有一条当前有效的判断用 `targets`、`coexists_under` 或 `opposes` 同时指向两边（或两边所引的段落），视为条件已写清，不再列出。同一来源内部的差异不算。条数上限沿用 `point_lint_max` |
| D-11 | **使用前须知随联想与展开返回**：`search_associate` 的每条结果、`entry_expand` 都带 `cautions`。要点的使用前须知是针对它所引段落（或整份原件）的使用约束——约束针对的是原件段落，要点引用了那一段就随附 |
| D-12 | **依据按原件分组显示**：条目页关系区里，同一种关系指向同一份原件的多个段落时收成一张卡：标题是原件名，标出"N 段"和用到的编号；卡内每行一段，写"[编号] 段落 · 作用 · 说明"，点行打开那一段；正文上标点击仍跳到对应的那一行。只有一段时照旧一张关系卡。要点页的出处用同一个组件，每行再带原文片段 |
| D-13 | **关系图默认显示要点，按原件折叠**：默认节点类型加上要点；一份原件的要点不少于 4 条时收成一个"要点 ×N"节点（边合并、计数相加），选中它在侧栏列出这些要点，可以"在图上展开"（只在本次浏览有效）。以原件为中心时它的要点默认展开；名称搜索命中的要点不折叠。浏览器里记住的旧"默认"视图自动补上要点 |
| D-14 | 前端共用论断组件 `claim.tsx`：`ClaimBody`（正文、条件、适用范围、原作者、对象、重开条件、本版改动）与 `CiteGroups`。判断页与要点页都用它；思路与约束没写条件时不显示"没写条件" |
| D-15 | 条目页标题下的一行（类型 · 第几版 · 作者 · 会话 · 时间）没有的项不占位；框架页的版本与作者取 `page.get`。修掉"要点 · · 今天"的空位 |
| D-16 | 关系图右上角的布局切换不再与左上角的搜索框重叠：搜索框给它留出位置，按钮不换行 |
