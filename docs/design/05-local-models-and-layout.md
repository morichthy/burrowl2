## 1. 背景（2026-11-08）

1. **公式抽取差**：内置抽取只读 PDF 文字层（pypdfium2）。行间公式按数学字体识别成 `formula` 块，但字符是按字形位置排的一串，结构丢失；行内公式只标出所在段落。LaTeX 目前只能由 AI 客户端看裁切图后提交，或人工填写（设计稿 03 D-17）。
2. **对照视图不还原版面**：右栏按阅读顺序排文字块，公式默认显示原件裁切图，Word 嵌入图片在原位置显示，但页面上的位置关系（分栏、图文混排、公式与编号）看不出来。抽取层其实已经有每块的位置 `box`（设计稿 02 D-03）。
3. **工作台以前不调用任何模型**（设计稿 04 D-16）。用户在 2026-11-08 放开了这一条，边界见 §2。

## 2. 调用边界（用户决定，2026-11-08）

| 类别 | 例子 | 调用方式 |
|---|---|---|
| **本地模型**：在本机运行、只做一件确定的事的专用模型 | 版面抽取（MinerU、Docling、PaddleOCR PP-StructureV3）、公式识别（UniMERNet、PP-FormulaNet、pix2tex）、向量模型 | 工作台**可以默认调用**：按设置在登记、补抽时自动运行，也可以在原件页手动运行 |
| **LLM**：通用大模型，不论在云端还是本机 | 命令行 agent（claude、codex）、OpenAI 兼容的对话 / 视觉接口 | **不自动调用，只能显式调用**：人在工作台点了某个按钮、在命令行明确执行，或 AI 客户端自己决定调用某个工具。登记、补抽、定时检查、任务队列里都不会调用 |

由此：

- 设计稿 04 D-16"不在工作台进程里调用模型"改为"工作台只自动调用本地模型；LLM 只能显式调用"。04 §5 不采用表中"在工作台进程里直接调用模型做复核"仍然不采用：AI 复核是 LLM 的工作，照旧经"交给 AI 复核"委托给用户的 AI 客户端。
- 已有的"交给 AI 识别""交给 AI 抽取""交给 AI 复核""交给 agent"不变，都是显式的。

## 3. 决定

### 模型连接与调用

| 编号 | 决定 | 理由 |
|---|---|---|
| D-01 | **burrowl 不打包、不启动模型**。每个模型是用户自己运行的本地服务（或命令），工作台只保存它的地址与类别，通过 HTTP 调用。设置页给出各工具的启动方法 | 模型与 GPU 依赖体积大（几百 MB 到数 GB），许可证各不相同（MinerU 3.1 起是自定义许可证）；与 ONLYOFFICE 的做法一致（设计稿 03 D-13） |
| D-02 | **四个槽位**，每个槽位在设置里选一个适配器并填写地址：<br>• `layout` 版面抽取：`mineru` / `docling` / `paddlex`（PP-StructureV3）/ 无；<br>• `formula` 公式识别：`unimernet` / `pp_formulanet` / `pix2tex` / 跟随版面引擎 / 无；<br>• `embedding` 向量模型：留位置，本稿不实现检索（§6 未决 4）；<br>• `llm` 通用大模型：OpenAI 兼容接口，可选，只用于显式按钮（D-08） | 槽位按"做什么"划分，适配器按"用哪个工具"划分；换工具只改设置 |
| D-03 | **自动运行的条件**：槽位是本地模型类别（前三个），**而且**地址是本机（`localhost`、`127.0.0.1`、`[::1]`）。地址不是本机的，同样只能显式调用。`llm` 槽位永远不自动运行，设置页没有"自动"选项 | 用户说的是"本地模型"；同一个工具部署在别的机器上，等于把原件发出本机，应由人每次决定 |
| D-04 | **调用在后台任务队列里进行**：工作台进程内一个队列，一次跑一个任务（模型通常独占 GPU）；调用期间放开数据目录的锁（`Workspace.unlocked`）；任务状态（排队、运行、完成、失败与原因）在底部状态栏的系统状态面板与原件页显示；失败不影响内置抽取的结果 | 版面抽取一份论文要几十秒到几分钟；不能让工作台卡住 |
| D-05 | **测试连接**：每个槽位有"测试连接"，调用适配器的健康检查并显示工具版本；版本号写进抽取记录 | 抽取结果要能追溯到工具与版本 |

### 版面抽取引擎的结果怎样进抽取层

| 编号 | 决定 | 理由 |
|---|---|---|
| D-06 | **默认只拿公式，不换段落**：配置了版面引擎时，登记 / 补抽仍由内置抽取器写段落（锚点、指纹不变），引擎的结果只用来给已有的 `formula` 块补 LaTeX，按 `box` 重叠度对应（IoU 不低于 0.5，同一页）；内置抽取没认出、引擎认出的行间公式，作为新的 `formula` 块插入（会改变这一页之后的段落编号，按现有机制让引用它的判断进待复核，D-07 的选项可以关掉插入） | 段落锚点是引用的地址；整份换成引擎的分段会让已有引用大批进待复核。公式是现在最差的部分，先补它 |
| D-07 | **整份替换为可选**：设置 `layout.mode`：`formulas`（默认，D-06）/ `formulas_only_existing`（只补已有公式块，不插入新块）/ `replace`（引擎的分段替换内置抽取，表格、图片、阅读顺序都用引擎的）。原件页也可以对单份原件"用版面引擎重新抽取" | 扫描件、复杂版面时引擎整体更好；但换分段的代价要由人决定 |
| D-08 | **可信度档**：引擎或公式模型补的 LaTeX，`latex_source.method` 记 `tool:<适配器>@<版本>`，可信度档记 `ocr`；`replace` 模式下引擎的段落也记 `ocr`（PDF 有文字层、引擎报告文字取自文字层的块记 `parsed`）。都需要人确认；被引用时照常提示 `LOW_FIDELITY_CITATION`（设计稿 04 D-06） | 模型识别可能出错；与 OCR 同档，现有的确认和提示机制直接适用 |

### 公式识别

| 编号 | 决定 | 理由 |
|---|---|---|
| D-09 | **公式块的显示不变**：没有 LaTeX 时显示原件裁切图；有 LaTeX 时用 KaTeX 排版，标出来源（工具 / AI / 人工）与是否确认，"对照原件"切回裁切图（设计稿 03 D-16、D-17） | 原图永远是最可靠的显示 |
| D-10 | **自动识别**：`formula` 槽位可用且满足 D-03 时，抽取完成后把还没有 LaTeX 的公式块裁切图（`clip`，3 倍）排进任务队列识别，结果按 D-08 写入。已有人工或 AI 提交的 LaTeX 不覆盖 | 本地公式模型一个公式不到一秒，可以默认跑 |
| D-11 | **显式识别**：公式块旁的按钮变为"识别"（用公式槽位，立即排队）、"交给 AI 识别"（不变，复制提示给 AI 客户端）、"用大模型识别"（只在配置了 `llm` 槽位时出现，点一次调用一次，`latex_source.method` 记 `llm:<模型名>`，可信度档 `ai`）、"填写 LaTeX"（不变） | 用户要求"可以优先直接以图片显示，再点击交给相应的模型转化"，模型在工作台配置；大模型只在点击时调用 |
| D-12 | **行内公式**：版面引擎会给出行内公式（`$…$`）的位置与 LaTeX。`formulas` 模式下，把它们记在所在段落块的新字段 `inline_math`（`[{text, latex, box}]`），段落文字不变；显示时在"文字""对照"里把这些片段换成 KaTeX | 行内公式目前只能标出段落；放在附加字段里不改变锚点与指纹 |

### 对照视图按版面还原

| 编号 | 决定 | 理由 |
|---|---|---|
| D-13 | **对照视图的右栏增加"按版面"模式**（工具栏切换"阅读顺序 / 按版面"，记在个人偏好）：每页画一张与原件同比例的白纸，各块按 `box` 绝对定位，文字按块高自动缩小字号；公式块显示 KaTeX（没有 LaTeX 时显示裁切图）；图片、表格显示裁切图或抽取的表格；页眉页脚（`furniture`）淡色显示。没有 `box` 的单元（文本文件、识别提交的文字）照旧按阅读顺序 | 抽取层已经有每块的位置；这样右栏的版面与左栏的原件逐块对应，看得出哪块抽错了 |
| D-14 | 原样视图（左栏）不变，仍由阅读器显示原件本身 | 还原版面只是为了核对抽取，不替代原件 |

## 4. 对不变式的影响

| 不变式 | 影响 |
|---|---|
| I1 账本只追加 | 引擎结果照常追加 content 记录；补 LaTeX 沿用设计稿 03 D-17 的复制写法 |
| I3 可信度由系统推出 | 引擎、模型结果的可信度档由方法决定（D-08），调用方不能指定 |
| I4 / I5 身份与只能由人做的操作 | 自动任务的调用者是系统（`system:model`）；确认抽取仍只能由人做。显式的"用大模型识别"记为人发起（`actor` 为人，`method` 记模型） |
| I8 落盘格式只增不改 | 新块字段 `inline_math`、新设置组 `models`；旧数据不受影响 |
| 抽取可以重建 | 引擎结果与内置结果都记在抽取层；`replace` 模式下，人工与 AI 提交过的单元仍保留（设计稿 01 D-19） |

新状态的归属：

- 模型设置（槽位、适配器、地址、密钥、自动开关）在数据目录 `config.json` 的 `models` 组，由设置页修改，只有人能改；密钥读取时不返回原文（同 ONLYOFFICE）。
- 任务队列只在工作台进程内存里，可丢弃。重启后，未完成的任务由"补抽"或原件页重新发起。
- 消费者：抽取层、阅读模式、系统状态面板。

## 5. 调研摘要（2026-11-08）

| 工具 | 做什么 | 许可证（实现前再核对） | 备注 |
|---|---|---|---|
| MinerU | PDF → Markdown / JSON，公式转 LaTeX，表格转 HTML，带位置 | 3.1 起为基于 Apache-2.0 的自定义许可证 | 学术、公式密集文档评价最好；可在 CPU 上运行；自带 HTTP 服务 |
| Docling | 多格式文档 → 结构化文档，含公式增强 | MIT | 混合格式最稳妥；难扫描件不如专门的视觉模型 |
| PaddleOCR PP-StructureV3 / PaddleOCR-VL | 版面、表格、公式 | Apache-2.0 | 精度高；VL 版需要 GPU、较慢 |
| UniMERNet | 公式图片 → LaTeX | 需核对官方仓库 | Tiny 到 Base，107M–325M |
| PP-FormulaNet | 公式图片 → LaTeX | 需核对 | 有 S / M / L |
| pix2tex | 公式图片 → LaTeX | 需核对 | 轻量，复杂公式较弱 |

适配器只依赖各工具公开的 HTTP 接口；第一批实现 MinerU（版面）与一个公式识别模型，其余按需添加。

## 6. 未决

1. 第一批先接哪个版面引擎、哪个公式模型。本稿建议 MinerU 加 UniMERNet；请用户用自己的几篇论文对比一次再定。
2. 局域网里的模型服务（例如另一台带 GPU 的机器）算不算"本地"。本稿取"不算，只能显式调用"（D-03）；如果常用，可以加一个"信任的地址"列表。
3. `formulas` 模式插入新公式块会改变段落编号（D-06）。是否默认关掉插入（即默认 `formulas_only_existing`）。
4. 向量模型槽位只留设置，检索怎样用向量（混合排序、评测）另写设计稿。
5. 引擎给出的表格（HTML）在 `formulas` 模式下是否也补到已有的块上。本稿不包含。

## 9. 修订（2026-11-09）：MinerU 作为 PDF 抽取方式、按文字层核对、自动启动

背景：用户在 Adam 论文上发现内置抽取把公式读成乱码（数学字体没有字符映射），补公式时截图也常不全（内置抽取把一条公式切成几块）。核对 MinerU 4.1.7 的源码与实测结果：文字层 PDF 被判为 `txt` 方式时，MinerU 的正文**取自 PDF 文字层**（读不出足够字符的小段才截图 OCR），版面模型只负责划分区域，公式区域另由公式模型按截图识别成 LaTeX。Adam 论文 286 段正文中 278 段与文字层逐字一致，其余 8 段只差文字层把帽子符号读成的 `b`，0 段明显不同。所以 MinerU 的分段可以同时拿到"区域划分准"和"文字可信"两头。用户决定：抽取方式里加 MinerU；没被引用的原件直接采用 MinerU 分段；按文字层核对逐块定档；缓存切换档位时直接覆盖；MinerU 由 burrowl 在需要时启动、用完关闭。

| 编号 | 决定 | 理由 |
|---|---|---|
| D-15 | **`extraction.pdf` 增加取值 `mineru`**（设置页"抽取方式"）。登记时照常先做内置抽取（马上能读、能搜），同时排进 MinerU 任务；不受 `models.layout_auto` 影响，但仍要求版面引擎已配置、地址是本机（D-03）。没有配置时按内置抽取处理，设置页提示。选 `mineru` 时"版面引擎的结果"（D-07）不再生效，设置页变灰并注明 | 用户在设置里选了 MinerU，就是要它分段；先内置抽取保证 MinerU 没开或出错时也有文字 |
| D-16 | **没被引用的原件直接采用 MinerU 分段**：MinerU 结果到达时，若还没有任何判断引用过这份原件（`cited_segments`，或引用了读过它的读取记录），整份替换为 MinerU 的分段（人工、AI、OCR 工具提交过的单元照旧保留）；已被引用的，按 `formulas` 补公式，原件页说明"已被引用，未替换分段"，人可以手动整份替换（仍只能由人发起）。修订 D-07"整份替换只能由人发起"：这种情况由人在设置里预先决定，而且不会让任何判断进入待复核 | 换分段的唯一代价是引用变化；没人引用时代价为零 |
| D-17 | **按文字层核对逐块定可信度档**（修订 D-08）：MinerU 判为 `txt` 方式时，正文与标题块只取文字片段（不含行内公式），规范化（NFKC、去空白与连字符断行）后在该页文字层里出现，或按字符能对上的比例不低于 97%，块记 `fidelity: parsed`；否则记 `ocr`。公式、表格块记 `ocr`；`ocr` 方式（扫描件）的块一律 `ocr`。块上的 `fidelity` 优先于单元的；单元的可信度档取各块中最低的一档。段落引用、`LOW_FIDELITY_CITATION` 按块的档 | MinerU 不标每小段的来源，只给整份的处理方式；逐块核对能把 OCR 补救过的小段挑出来，不需要人逐段确认可信的正文 |
| D-18 | **缓存记下档位，档位不同就重跑**：MinerU 结果缓存（`cache/models/mineru/<sha256>.json`）记下 `tier`；设置里的档位与缓存不同，或人点"用版面引擎重新抽取"时，重新调用并覆盖缓存。不同档位的比较看原件页的抽取历史（账本保留每一次抽取） | 缓存只是可再生的副本；比较依靠账本，不需要按档位各存一份 |
| D-19 | **burrowl 在需要时启动 MinerU、空闲后关闭**（修订 D-01"不启动模型"；仍不打包、不安装）。设置 `models.layout_launch`：`manual` 自己运行（默认）/ `auto` 需要时启动；`models.layout_cmd` 启动命令（默认 `mineru-api`，可填完整路径）。启动参数为 `--host 127.0.0.1 --port <地址里的端口>`，档位不是 `auto` 时加 `--tier <档位>`；只有地址是本机才启动。Windows 上在新的命令行窗口里运行（标题"burrowl · MinerU"，可以看到下载与处理进度）；其他系统在后台运行、输出写到 `cache/models/mineru-launch.log` | 用户不想每次手动开 MinerU；命令由人在设置里填写，AI 不能修改（`settings.set` 只有人能调用） |
| D-20 | **启动记录与关闭**：启动记录 `cache/models/mineru-launch.json`（进程号、端口、启动时间、最后使用时间）。任何进程用之前先查健康检查：已在运行就直接用（不是自己启动的不关闭）；用时更新最后使用时间。启动它的进程在自己的队列空了、且最后使用已过 10 分钟时关闭（连同子进程）；进程退出后留下的 MinerU，由下一个需要它的进程接管 | 工作台进程和 MCP 进程各有任务队列（§6 已知差距），共用一个 MinerU 服务；记录放在数据目录的缓存里，可以随时删 |
| D-21 | **测试连接自动启动**：`manual` 时与原来一样；`auto` 时若连不上，先启动、等健康检查通过（第一次运行要下载模型，最多等 30 分钟，设置页显示"正在启动"），报告版本后，若是这次测试启动的就关闭。命令找不到时提示安装命令（burrowl 不替用户安装） | 一次点击完成"能不能跑起来"的检查，不留下常驻进程 |
| D-22 | **公式截图用整条公式的范围并留边**：裁切图优先用 `latex_box`（补公式时算出的整条公式范围），四周各留出块高的 15%（至少 4 pt）。采用 MinerU 分段的原件，公式块本身就是整条公式 | 截图不全是"识别"与 AI 核对不准的主要原因之一 |
