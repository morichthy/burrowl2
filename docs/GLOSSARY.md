# 术语表

每个术语只在这里给出权威的短定义：它是什么、不是什么、代码中的标识。其他文档首次出现时链接这里。

## 模型

| 术语 | 定义 | 不是什么 | 代码标识 |
|---|---|---|---|
| 三列 / 综合程度 | 内容按综合程度分成原件、判断、框架三列 | 不是可信度等级 | `layer`：`original` / `judgment` / `framework` |
| 条目 / 关系 / 坐标 | 设计稿 10 的三个部分：**条目**是节点，只存推不出的事实；**关系**是主语—谓词—宾语，一条一行，两端固定到版本；**坐标**是读取时推出的可靠程度与现状 | 凡是"A 与 B 之间"的事都是关系，不是字段 | 账本基表、`relations`、`services/coordinates.py` |
| 坐标 | 一个条目某一版的四组读时推出的值，按显示顺序：**地位**（综合程度 `layer` × 依据来源 `sources`）→ **类型**（`kind`）→ **现状**（`state`：有效性、复核、现状标记）→ **说明**（`notes`：最终作者、原作者、说明标记）；`status_note` 是它的一行说明（设计稿 10 D-12） | 不是一个分数；不决定检索名次；不落盘 | `CoordinateService.of`、`compact` |
| 地位 | 只指双轴：综合程度 × 依据来源；只由条目这一版自己的依据决定，别人后来的佐证或反驳不改变它（设计稿 10 D-13） | 不含复核、被替代等现状 | 坐标的 `layer`、`sources` |
| 来源记号 | 依据来源的写法：`local`、`external:peer_reviewed` / `preprint` / `vendor` / `web`、`external`（未分档）、`inferred` | — | 坐标 `sources`；`vocab.SOURCE_LABELS` |
| 有效性 | 现状的一部分：当前有效、被替代（有更新的版本或被人确认的替代）、已撤回、已退役、依据失效 | 不是地位 | `state.validity` |
| 标记 | 坐标里的例外情况，每个带出处 `via`（造成它的关系与另一端）。现状标记：被佐证、被反驳、依据有变化、部分依据已失效、本版有缺陷、输入已变化、未核查；说明标记：依据含未确认的识别、转述但没写条件、依据边界不完整、结论没有依据、人标了本地实证、本地依据的独立来源（设计稿 10 D-14） | 不是字段；只在出现时列出 | `vocab.MARKS`；`state.marks`、`notes.marks` |
| 谓词 | 关系的种类。核心谓词由系统依赖其含义：依据 `cites`、佐证 `supports`、反驳 `opposes`、条件并存、回答、针对、替代、用到、产出，以及框架推断的几种；核心谓词都不合适时用 `relates` 加自由标签（设计稿 10 D-08、D-09） | 自由标签不算依据、不产生标记 | `vocab.PREDICATES` |
| 依据 / 佐证 | 依据 `cites`：A 依据 B，证据从 B 流向 A，参与 A 的依据来源；佐证 `supports`：B 事后为 A 作佐证，A 的地位不变，现状里出现"被佐证"（设计稿 10 D-08、D-13）。2.0 的"引用、依赖、出处"都并入依据 | — | `cites`、`supports` |
| 原件 | 原文如实的内容：登记的文件或文本、过程日志、事实记录 | 不是"关于世界的事实"；原件里的内容只能以"某来源说了 X"引用 | `art_` / `evt_` / `rec_` |
| 判断 | 当时谁、依据什么、认为了什么。只追加，不裁决，冲突可以并存；可以复核它与依据是否对得上，复核记为它的变更历史，不改它本身 | 不是"现在该信的结论"（那由框架回答） | `jdg_`，表 `judgments` |
| 框架 | 实体、实体页、概念页、综合页、描述页、关系图的边、索引。可以再生 | **永远不能作为依据** | `ent_` / `pg_` / `edg_` |
| 依据来源 | 依据从哪里来：本地实证、外部报告（分档）、推断。三类没有固定高低；判断的依据来源由它这一版的 `cites` 推出 | 不是作者身份 | 原件 `source_class`；坐标 `sources` |
| 本地实证 | 在本项目内执行、测量或直接观察得到的依据（旧称"亲自执行"）。人写结论时可勾选；AI 的执行通过过程日志和事实记录留痕 | 不是"可信"的同义词 | `local`；`local_observation` |
| 推断 | 由推理、讨论或 AI 生成、没有直接观测的依据（旧称"推断或讨论"） | — | `inferred` |
| 外部报告细分 | 外部报告的类型：同行评议、预印本、厂商资料、网页 | — | `external_tier` |
| 全部依据为本地实证 | 依据来源只有本地实证（旧称"我们验证过的"）；从坐标现推，不另设字段 | 混合了文献的不算 | `sources == ["local"]` |
| 结论 | 关于对象的陈述，可以作为依据 | — | `conclusion` |
| 过程 | 提问、尝试、停下的路线（可带重开条件）、目的。是重新综合框架的依据；不能作为结论的依据；探索模式默认不返回 | 不是证据 | `process`；`reopen_condition` |
| 规定 | 约束、决定、指令：规定该怎么做，不陈述世界怎样，不参与真假排序 | — | `normative` |
| 处置 | 人对条目某一版的处置：撤回（判断）、标缺陷（原件一列）、退役（原件）及它们的取消；记在版本上（设计稿 10 D-04）。更正不是处置，是新版本 | 不是判断；2.0 的更正、撤回、缺陷判断已不再存在 | 表 `version_states`，`entry.version_state` |
| 原件退役 | 人决定一份原件不再单独出现（例如旧的派生文本已由原件自己的抽取层取代）：不进条目列表、默认检索、建页门槛和定时检查，仍可打开、阅读、引用；可以写明替代它的原件；撤销退役即恢复（设计稿 02 D-11 至 D-15）。记为原件的状态历史，不是判断（2.0.0a14） | 不是删除，也不是原件缺陷（不说内容有错）；不改变引用它的判断的可信度 | 表 `retirements`（`ret_`），`artifact.retire`；旧版的 `retirement` 判断与关系 `retires`；`include_retired`；提示 `RETIRED_CITATION` |
| 原件替换 | 人给已退役或已删除的原件指定替代原件：引用旧原件段落的判断按段落指纹在替代原件里核对，对得上的照常有效，对不上的进入待复核（设计稿 07 D-03） | 不改写任何判断，也不改旧原件 | 表 `replacements`（`rpl_`），`artifact.replace`；坐标 `replaced_by` |
| 依据失效 | 判断或事实记录的依据最终落在"已退役且没有替代"或"已删除且没有替代"的原件上。全部依据失效的有效性为"依据失效"、默认隐藏（不进列表、检索、关系图、统计）；部分失效的现状里有"部分依据已失效"标记，出处列出失效的依据（设计稿 07 D-01、D-02，设计稿 10 D-20） | 是读时推出的，不写账本；恢复或替换后自动复原；只看依据（`cites`），不看佐证、反驳 | `state.validity = lapsed`；标记 `basis_lapsed` |
| 原件删除 | 人彻底删除一份已退役的原件：连同读取、抽取、退役记录、依据全部来自它的条目、相关系统流水一起删掉，不留记录、不能撤销；部分依据来自它的条目保留，标为"所引原件已删除"（设计稿 07 D-04、D-05） | 不同于退役（退役什么都不删）；数据目录以外的备份不受影响 | `artifact.delete_preview`、`artifact.delete`（`confirm`）；`purge_gate` |
| 本地模型 | 在本机运行、只做一件确定的事的专用模型（版面抽取、公式识别、向量模型）。地址是本机时，工作台可以在登记、补抽后自动调用（设计稿 05 §2） | 不是大模型；burrowl 不打包、不安装它；MinerU 可以设成需要时按你填写的命令启动、空闲后关闭 | 设置组 `models`（槽位 `layout`、`formula`）；向量与重排模型是 `index.embedding_model`、`index.rerank`（设计稿 06） |
| 大模型 | 通用大模型（命令行 agent、OpenAI 兼容的对话 / 视觉接口），不论在云端还是本机。只在人显式点击或执行命令时调用 | 不会在登记、补抽、定时任务里被调用 | 槽位 `llm`，CLI 后端按 `llm_agent` 引用 Agent 配置；"用大模型识别" |
| 版面引擎 | 本地的版面分析模型（目前是 MinerU）：给 PDF 的公式块补 LaTeX、给段落记下行内公式；默认不改段落与锚点，也可以整份替换抽取 | 补的 LaTeX 按 OCR 档对待，需要人确认 | `artifact.layout_engine`；`layout_mode`；来源 `tool:mineru@版本` |
| MinerU 分段 | 抽取方式 `extraction.pdf=mineru`：还没被引用的 PDF 改用 MinerU 的分段；每块与该页文字层核对，对得上的记"解析文字层"，对不上的和公式、表格记"OCR 识别"（逐块定档） | 已被引用的原件不换分段，只补公式 | 块字段 `fidelity`；设计稿 05 D-15 至 D-17 |
| AI 已核对 | 大模型看图核对过一块 OCR / AI 识别的文字或公式，认为与原件一致 | 不等于人已确认，可信度档不变；只对当时那条抽取有效；整份原件都已核对一致时不再进待决策；AI 引用它写的判断带 `recognition_unverified` 标注（设计稿 04 D-26） | `extraction.ai_check`；`reviews` 里 `anchor`、`part`；设计稿 04 D-22 至 D-24 |
| 公式分组 | 内置抽取把一条公式切成几块时，版面引擎把落在同一条公式范围里的几块并成一组：第一块带整条 LaTeX，其余几块显示时并入它 | 不改段落文字与锚点 | 块字段 `latex_group`、`latex_box`、`latex_parts` |
| 按版面 | 对照视图文字栏的一种显示：每页一张与原件同比例的纸，各块按位置摆放（设计稿 05 D-13） | 只为核对抽取，不替代原件 | 个人偏好 `textLayout` |
| 复核记录 | 一次复核（确认、驳回、拿不准）或"请人复核"：被复核条目的变更历史，带理由、补充的依据、方式（人 / AI）与模型名（设计稿 04 D-18） | 不是条目：不进检索、不出现在列表、不能被引用 | 表 `reviews`（`rev_`），`review.history` |
| 撤销复核 | 人让指定人工复核或当前抽取版本的确认失效，追加理由并按剩余有效记录恢复状态 | 原复核记录仍可查看 | `review.revoke`，`reviews.data.revokes` |
| AI 复核 | AI 对照原件层、判断层核对一个条目：只接受 AI 生成未复核的框架页与关联边（设置允许时还有待复核的判断），依据要相关、本会话读过，不复核本会话写的，拿不准交 unsure（D-12 至 D-15） | 不等于人已复核；不能隐藏内容、不能写回判断层 | `review.ai_submit`；设置 `review.ai`；状态 `ai_reviewed` |
| 请人复核 | 任何人或 AI 把一个条目加入待决策列表，附一句要看什么（D-17） | 不改变条目的状态 | `review.request` |
| 引用待复核的判断 | 新判断引用或支持一条依据已变化、还没有人复核的判断：写入成功，只提示（D-11） | 不拒绝写入 | 提示 `RECHECK_CITATION` |
| 定期巡检 | 定期检查近期研究：原件与结论是否冲突、遗漏，条目是否符合记录规则，并抽样阅读没人读过的段落（设计稿 08） | 不是自动改判断；定时只准备，不调用大模型 | 服务 `inspection`；设置组 `inspection` |
| 巡检包 | 一期巡检的范围与任务清单：规则检查找出的可疑项和探索样本，每项写明要读的段落和要回答的问题 | 任务只说明“这里可疑”，不是发现 | 表 `inspections`（`insp_`），`inspection.prepare` / `inspection.get` |
| 经验未收录 | 巡检检查项：本期有实际操作（本地实证的操作日志及其产出），却没有任何判断提到；按会话分组成任务（设计稿 08 D-40） | 不是自动写判断：巡检员报、复核员按类型提拟写判断，人确认后才写入 | 检查项 `uncaptured`，建议 `capture`；设置 `inspection.uncaptured_max`；`review.ai_submit` 的 `proposed_kind` |
| 转述 | 结论转述外部材料（文献、厂商资料、网页）中的发现时，填原作者；说明里显示"转述 · 原作者 …"。依据来源照常由依据推出，本地验证后现状里有"被佐证（本地实证）"（设计稿 10 D-15） | 不是独立的判断类型或类别；2.0 的"转述的结论"不再使用 | `external_author`；坐标 `notes.quoted` |
| 消化 | 外部原件登记后，AI 读原件、把材料自己的发现写成转述的结论、并进相关综合页，最后记一条消化记录；原件出了新版本重新进入待消化（设计稿 09 D-04 至 D-09） | 不是摘要，不评价、不补条件；工作台不自动调用大模型 | `digest.*`、`services/digest.py` |
| 转述但没写条件 | 转述外部材料的结论没有写条件（原文没给的应写"原文未说明：……"）；写入照常成功，返回提示，说明里带这个标记（设计稿 09 D-08、设计稿 10 D-14） | 不是错误 | `CONDITIONS_UNSTATED`；标记 `conditions_unstated` |
| 高依赖的外部结论 | 巡检检查项：只有外部报告或推断作依据的结论，被多条判断或多份页面依赖，却没有本地实证支持（设计稿 09 D-20） | 不是说它错了 | 检查项 `external_reliance`，建议 `verify_local`；设置 `inspection.reliance_max` |
| 依据构成 | 框架页的输入里有几条本地实证、外部报告、推断，其中几条结论只有外部依据；由系统算出，不写进正文（设计稿 09 D-12） | 框架内容，不能作为依据 | `basis_mix` |
| 巡检发现 | 巡检员读原件后提交的问题：针对哪些条目、依据哪些段落、建议怎样处置。每条就是一项待决策（设计稿 08 §9） | **不能被引用**，不写回判断层；不另开请人复核 | 待决策 `kind=finding`（`dec_`），`inspection.submit`、`finding.resolve` |
| 巡检员 / 复核员 | 巡检员（辅 agent）领取巡检包、提交发现；复核员（主 agent）对每条发现自己重读原件后确认、驳回或拿不准。都由人点按钮启动 | 复核员的意见不等于人已处理 | 设置 `inspection.inspector` / `inspection.reviewer`；`review.ai_submit(dec_…)` |
| 巡检原则 | 给巡检员、复核员的工作原则，随领取结果交给 AI；人在设置页改，清空即回到默认原则（设计稿 08 D-36） | 不是系统强制的规则：先读后报、依据只能是原件层与判断层等写在代码里，改原则不会放宽 | 设置 `inspection.guidelines`，`inspection.guidelines` 操作 |
| 覆盖图 | 原件段落的五档：被引用、读过未引、命中未读（多次被检索返回却没人读）、相关未读（和近期判断最相关却没人读）、冷区 | 不是指标；没读过不等于有用；框架内容，不能作为依据 | `coverage.view`；检索命中记录（过程日志 `search` 事件） |
| 阅读会话 | AI 通过 MCP 查询 burrowl 的一个会话：读了什么由读取记录、检索命中、写下的判断读时算出；目的、认知、handoff 是 AI 用 `reading_note` 写的过程笔记 | 笔记是过程内容，不能作为依据；handoff 是 AI 提交的快照 | 事件 `reading.note`，操作 `reading.note` / `reading.list` / `reading.get`，设计稿 11 |
| 不外发 | 人把一份原件标为不外发：它的原文不进巡检包，巡检会话里读不到、检索不返回 | 平时的 AI 会话不受影响；不是退役 | 表 `artifact_policies`（`pol_`），`artifact.policy`；错误码 `NOT_OUTBOUND` |
| 低影响待决策、抽查 | 影响范围为 0 的待决策项默认折叠；每周从 AI 生成未复核的框架页里固定挑几页给人看（D-07） | 不是规则：只是为了先看后果大的 | `decisions.impact`；`review.sample` |
| 判断类型 | 写的人在结论、过程、规定三种中选择（AI 在 `judgment_write` 中填写，人在工作台选择）；另有系统记录。旧称"言语类型"（D-14 前有 12 种） | 不是系统推断出来的 | `judgments.kind`；`WRITABLE_KINDS` |
| 条目版本 | 条目 ID 稳定，版本写 `@n`（`jdg_…@3`、`art_…@2#p3-2`）；当前版 = 最新版。AI 改写自己会话写的判断、人更正任何条目都写新版本，沿用上一版的原作者、对象、关系；"重新生效"写成复制那一版的新版本（设计稿 10 D-01、D-02） | 不是新条目；引用固定在当时的那一版 | 基表 `*_versions` 的 `(id, version)`；`services/versions.py` |
| 读取记录 | 读了哪份原件、哪个版本、哪一段，以及读到的原文；自动日志，不作为条目显示，在原件页的段落旁查看（设计稿 01 D-03） | 不是摘要；不是判断的必经依据 | `rd_`，表 `reads` |
| 抽取层 | 原件的可读文字，按单元（PDF/PPT 的页、Word 正文、图片、音视频）组织，带版式块和可信度档；索引、工作台显示、读取、引用都来自它（设计稿 01 D-10） | 不是另一份原件；原件字节始终原样 | 表 `extractions`，`ex_` |
| 可信度档 | 抽取文字的来源：原样复制 > 解析文字层 > 人工转写 > OCR 识别 > AI 识别；可由人确认 | 不是判断的可信度 | `copy` / `parsed` / `manual` / `ocr` / `ai` |
| 原件段落 | 引用原件内容的写法 `art_…#段落`：`seg-N`（文本、Word）、`p3-2`（第 3 页第 2 段）、`img-1`、`av-4`；写入判断时记下段落指纹 | 不是读取记录 | `cited_segments` |
| 对象 | 条目讲的是什么东西：实体（`ent_…`）或规范化的叫法；一条可以有多个；用于对象页、约束检查、建页门槛 | 不是标签分类 | 表 `entry_objects` |
| 页面快照 | 用本机 Office / LibreOffice 把 PPT、Word 转成的 PDF，只用于在工作台按原样显示 | 不进索引，不能引用 | 抽取记录 `snapshot` |
| 原样显示 | 原件页按原件本来的样子显示：PDF 用 PDF.js，Word 用 docx-preview，PPT 用页面快照；段落标记按块的位置画在上面（设计稿 02 D-01） | 不是抽取层；看到的版式不影响检索与引用 | `pages/Faithful.tsx` |

| 页眉页脚 | PDF 中多页同一位置重复的行、页码、页边竖排编号：保留在块里供显示，不进索引、不分段 | 不能引用 | 块类型 `furniture` |

| 公式 LaTeX 补充 | AI、OCR 工具、本地版面引擎、大模型或人给公式块补上 LaTeX：只在块上加 `latex` 与来源（方法、可信度档），段落文字、锚点、指纹都不变，已有引用不进待复核；人确认单元时一并确认（设计稿 03 D-17） | 不是重新抽取；只用于 `formula` 块 | `artifact_extract` 的 `blocks`；块字段 `latex`、`latex_source` |
| 表格块 | Excel 原件每个工作表一个单元（`s1`、`s2`…），按整行空白分开的区域成块，大区域每 50 行一块，块记下单元格范围（设计稿 03 D-11） | 不含格式、图表、图片 | 块类型 `table`，字段 `range`（如 `A1:F20`） |
| 外部阅读引擎 | 用户自己运行的 Office 文档服务（目前是 ONLYOFFICE Docs），阅读模式通过签名的只读配置让它显示原件，它凭一次性令牌从工作台取文件（设计稿 03 D-13） | 不是 burrowl 的一部分，不打包、不启动；不能写回 | 设置 `viewer.onlyoffice_*`；`interfaces/engines.py`；`viewers/onlyoffice` |
| 阅读模式 | 全屏阅读一条原件或条目：外壳提供工具栏、侧栏（段落、引用、目录）、对照与文字视图，原件由可更换的阅读器显示（设计稿 03 D-01、D-02） | 只读，不写账本 | 路由 `#/read/{id}`；`frontend/src/reader/` |
| 阅读器 | 阅读模式里负责把某种格式原样显示出来的组件（PDF.js、docx-preview、文本 / Markdown、图片、音视频），通过阅读器契约接收原件来源与标注、发出点击与位置事件；每种格式的默认阅读器是数据目录设置 | 不是工作台页面；拿不到账本的写入能力，标注只显示不写回原件 | `frontend/src/viewers/<名称>/`；契约 `reader/contract.ts`；设置 `viewer.<格式>` |
| 事实记录 | 从过程日志或原件片段升级而来的正式条目：对象、条件、方法、结果（逐字）、边界、缺口。方法写到不知道目的的人也能复现或核对，其中的定义用 `cites` 指向原件段落（设计稿 07 D-07） | 条件不能事后补写；缺口不写目的 | `rec_`，表 `records`；关系 `documents`（出处） |

| 输入清单 | 框架条目生成时依据的不可变单元及其版本 | — | 表 `derivation_inputs` |
| 时效 | 框架条目的输入是否变化：有效、输入已变化、被替代、未核查。只降不升 | 不是复核状态 | `freshness` |
| 复核状态 | 条目是否经复核：AI 生成未复核、AI 已复核（地位与未复核相同）、人已复核、被驳回 / 复核未通过、按规则。框架页与边存在 `review` 列，判断从复核记录算出 | 不改变判断层的内容 | `review`；`ai_generated` / `ai_reviewed` / `human_reviewed` / `rejected` / `rule` ；判断的在坐标里写作 `state.review`（`none` / `ai_confirmed` / `ai_flagged` / `ai_unsure` / `human_confirmed` / `human_rejected`） |
| 传播 | 依据变化后，把下游框架条目标为"输入已变化" | 不修改判断 | `Propagation.propagate` |
| 术语连接 | 把一个叫法连到实体，分确定、较有把握、拿不准三档 | 不按 AI 自报的把握分档 | `LinkingService.link_term` |
| 别名表 | 人决定过的"叫法 → 实体"对应 | AI 不能直接写入 | 表 `aliases` |
| 检索单元 | 索引里把同一份原件相邻的引用段落合并成的召回单位（约 300、至多 400 token，遇标题断开），带"标题 › 小节"的机械上下文；命中后再落回单元里最相关的段落（设计稿 06 D-01） | 不是引用段落，不能被引用；只在索引里，随时可重建 | 表 `units`；`index/units.py` |

| 字面查找 | 逐字查找含有某段文字的段落，不分词、不排序 | 不是检索排序 | `search.exact` |
| 联想 | 从检索命中或给定条目出发，沿已有关系（判断关系、引用、输入清单、实体提及、共享对象、向量近邻）走 1–2 跳找到的条目，带路径 | 不是检索命中，相关与否要读原文判断；不是默认检索的一部分 | `search.associate`；`via` |
| 复用模式 / 探索模式 | 检索时三列都返回 / 不返回框架、展开时不给解读 | — | `search(mode=…)` |
| 待决策 | 等人处理的事项：术语连接、待复核、需重新综合、操作前未检查约束、传播超限 | 不阻塞写入 | 表 `decisions` |

## 程序与运行

| 术语 | 定义 | 代码标识 |
