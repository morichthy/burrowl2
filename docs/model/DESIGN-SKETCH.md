# 从头设计：记录与记忆的底层模型

## 本文件的作用

- 假设从零开始设计一个 AI 原生的记录与记忆系统，**不以 burrowl 的现有结构为前提**。
- 依据只来自本目录：问题以 [CORE-PROBLEMS.md](CORE-PROBLEMS.md) 为准，文献依据见 [FIELD-SURVEY.md](FIELD-SURVEY.md)，验证方法见 [EVAL-FRAMEWORK.md](EVAL-FRAMEWORK.md)。
- **先定底层模型，再逐条检验它对 CORE-PROBLEMS 各问题的覆盖情况。**原来按问题逐条设计的做法已放弃：一个决策会同时影响多个问题，逐条讨论认知负荷太大。
- 只写核心思路，不写接口和实现细节。
- **只写经用户认可的内容。**被放弃的思路移出时注明原因（见第 8 节）。

## 1. 两个轴

记录按两个独立的轴定位，取代原来的三层（真源 / 判断层 / 视图层）。

**综合程度**，分三列：

| 列 | 是什么 | 能否作为依据 |
|---|---|---|
| 原件 | 原文如实 | 能 |
| 判断与经验 | 当时认为了什么 | 能，但要标明来源 |
| 框架、导航、讨论稿 | 组织其他条目的内容 | **不能** |

**依据来源**，分三类，彼此没有固定高低：

- 亲自执行或测量；
- 外部报告：文献、外部文档、厂商资料；
- 推断或讨论。

各类内容的位置：

| 内容 | 依据来源 | 列 |
|---|---|---|
| 执行记录、实验数据 | 亲自执行 | 原件 |
| 文献原文 | 外部报告 | 原件 |
| 对话原文 | 推断或讨论 | 原件 |
| 文献中的论断 | 外部报告 | 判断与经验。作者记为原作者，同时记下提取者 |
| 人的第一手观察、指令、约束、决定 | 待定（第 9 节） | 判断与经验 |
| 执行时声明的目的、属于哪个问题、对过程的解读 | — | 判断与经验 |
| 关系图、实体页、概念页、综合页、检索索引、非文本原件的描述、讨论稿 | — | 框架（第 11 节） |

## 2. 存储分档

- **轻量过程日志**：保存所有操作和输出，以及捕获时就能自动获得的条件。不进入默认检索。
- **正式条目**：日志被判断引用或被明确标记时，才升级为正式条目，进入检索。"查了但没找到"也可以升级。

理由：当下往往不知道哪条事实将来有用。全部保留日志，防止信息丢失（K7）；只让被使用的部分进入检索，防止噪声（K3）。

## 3. 原件

**原件中的事实记录要最小可独立成立**：单独拿出来看，仍然成立、仍然有用。每条自带五项：

- 对象；
- 条件；
- 方法；
- 结果，逐字保留；
- 边界：截断、只读了一部分、受权限限制。

**目的无关检验**：换一个目的完全不同的人来读，这段上下文是否同样成立、同样需要？不通过的内容移到判断与经验一列。

其他规则：

- **条件必须在发生的当下记录。**升级为正式条目时只能整理，不能补写；缺失的明确标为缺口。
- **抬头只放可核对的元数据**，不放 AI 总结。
- **过程中可以核对的事实留在原件**：执行者、所在会话或子 Agent、时间及先后顺序。
- **只移走目的、问题归属和对过程的解读**，操作和过程本身留在原件。
- **整份原件不预先拆分。**被实际读到时，才产生一条读取记录：哪份原件、哪个版本、哪个范围、读到的原文片段。
- **对象和条件字段要写得规范、可以对齐。**事实之间靠共享的对象和条件连接（如设备编号、时间），不靠思路。目标是从原件就能完成大部分事实层面的逻辑重构，判断层只反映当时的思路和经验。

## 4. 判断与经验

- **只追加**：改写就新增版本，指向旧版本并说明原因。
- **引用所依据的条目**，并记下这些依据的全部来源类型。
- **写得能独立看懂**：写全对象和条件，不用指代词。只为可复用而补全，不附加背景和思路。
- **判断之间的局部关系属于这一列**：依赖、支持、反对、回答、替代、在某条件下并存。这些关系本身也是判断。
- **原子判断和综合经验不再细分**，只守住判断与框架的界限。
- **不裁决，冲突可以并存**（2026-11-08 修订，原为"不复核、不裁决"）。判断层是"当时谁依据什么认为了什么"的历史记录，只要依据真实存在就成立；两个人或两个时间点得出不同判断，本身就是事实。后来的变化不回头改它。"现在该信什么"由框架回答（第 11 节）。
- （2.1 修订，设计稿 10 D-05、D-12：不再存写入时快照；坐标由这一版自己的依据关系读时推出，引用固定到版本，所以与"写入时就能确定"等价。）
- **写入时可信度属于判断**：写入时就能确定、之后不变的部分，即依据来源的类型、是否基于亲自执行、谁做的判断、依据是否完整。会随后来证据变化的"当前可信度"属于框架，由框架重新计算；否则判断又会变成可修改的。
- **复核结论记入账本**（2026-11-08 修订，原为"写成一条新判断"）：人复核框架中 AI 的裁决（例如确认"A 替代 B，理由是……"）或核对一条判断与它的依据，结论作为被复核条目的变更历史记在账本表 `reviews` 里，不另写判断；确认"可能替代 / 可能矛盾"时直接写一条替代 / 反对链接，作者是复核的人。框架重建时不会丢失。判断的写入时可信度不变，当前地位由依据加上复核时补充的依据重新推出（设计稿 04 D-18、D-19）。

**更正与撤回**：

- **只由人通过人工修改入口发起。**对用户来说，这个入口就是"修改"；底层不改原条目，而是写一条新判断，指向原判断，关系是以下两种之一：
  - **更正**：原来就是错的，附理由；
  - **撤回**：不再主张这个判断。
- **AI 不能更正或撤回。**AI 认为某条判断不对时，只能写一条新的"反对"判断，由框架层裁决（第 11.2 节）。否则就等于判断层被 AI 改写了。
- **原件出错也不改原件。**例如仪器标定错误、记录抄错，用同一个入口写一条"某份原件有缺陷"的判断，并说明缺陷是什么。
- **后续流程与其他新判断相同**：沿输入清单追溯引用，把受影响的框架条目标为"输入已变化"，由 AI 重新综合，再交人复核（第 11.4 节）。

**判断与框架的区分**：

| | 判断 | 框架 |
|---|---|---|
| 内容 | 有明确的对象和条件，引用具体依据 | 概括一个方向，主要在组织其他条目 |
| 推翻 | 能指出什么证据可以推翻它 | 推翻它要推翻一批条目 |

判断里不允许出现：假设树、主线叙事、分类体系、"目前有三种思路"这类归纳，以及"显然""关键在于""根本原因是"等评价性措辞。理由：框架一旦进入不可丢弃的层，就会持续影响后来的人怎么读其中的每一条（K2、1.8）。

## 5. 问题的处理

问题既是历史事实，又带框架：问法有预设，聚合就是组织，问题本身也无法被推翻。因此拆成三部分：

| 部分 | 放在哪一列 |
|---|---|
| 提问这件事：谁、什么时候、逐字问法 | 判断与经验 |
| 某条判断针对哪个问题：一条"针对"关系，一条判断可以针对多个问题 | 判断与经验 |
| 聚合与层级：问题下挂什么、主问题和子问题、合并与拆分 | 框架，由视图生成 |

- 存储上不嵌套。
- 问法中的预设不当作事实，需要核实时单独写成一条判断。
- 尝试中实际执行的操作属于原件；为什么停下、什么条件下值得重新打开，属于判断。

## 6. 规则

1. **依据只能指向左边的列**，框架这一列永远不能作为依据。
2. **只有全部依据都来自亲自执行或测量的条目，才能称为"我们验证过的"**；否则要标明混合了哪些来源。亲自跑过的东西是唯一有特殊地位的来源。
3. **能再生的内容放在框架这一列。**
4. **原件中的内容只能以"某来源说了 X"的形式引用**，不能当作"X 为真"。
5. **默认展示顺序**（只用于展示，不是地位规则）：
   1. 亲自执行的原件；
   2. 实验数据；
   3. 基于数据的判断；
   4. 综合经验；
   5. 外部文献；
   6. 综合页、讨论稿等框架内容。

构建原则：

- 向下锚定：只要求依据可追溯，不要求内容能由下层推导；
- 每层只增加下层装不下的东西，并标明增加了什么；
- 按能否再生判定归属；
- 下层不依赖上层。

## 7. 检索路径

| 查询类型 | 路径 |
|---|---|
| 模糊查询 | 综合页、实体页和关系图 → 判断 → 原件 |
| 精确查询（设备号、错误码） | 直接命中，再沿引用展开 |
| 历史类查询 | 按对象和时间精确过滤 |

检索到一条原件记录时，按以下顺序展开背景：

1. 自带的条件；
2. 同一来源中的前后内容；
3. 同一对象的其他记录；
4. 引用了它的判断。这一项明确标为解读，探索时可以隐藏。

## 8. 关键理由与被放弃的思路

| 思路                                                | 处置                | 原因                                                                     |
| ------------------------------------------------- | ----------------- | ---------------------------------------------------------------------- |
| 三层：真源 / 判断层 / 视图层                                 | 改为两个轴             | 文献既有原件属性又有判断属性，三层难以归类                                                  |
| 单一地位阶梯：亲自跑过 > 实验数据 > 原子判断 > 综合经验 > 未经证实的文献 > 综合页等 | 保留为默认展示顺序，不作为地位规则 | 它同时回答"依据从哪里来"和"综合到什么程度"两个问题；未经复核的综合经验不一定比同行评议、被独立重复的文献更可信              |
| 依据来源排序、混合来源"取最弱"                                  | 改为不排序、记下全部来源      | "外部报告 > 推断"无法一概而论                                                      |
| K1 的"五类地位"和"四个维度"                                 | 不采用               | 先定底层模型；地位问题由两个轴和第 6 节规则承接                                              |
| 原始层与判断层合并成一个事件流                                   | 不采用，仍然分开          | 合并的理由是判断层就地修改会丢历史，改为只追加后不再成立；人也会说错，人的判断和观察不进入原件                        |
| 原件记"关于世界的事实"                                      | 改为"原文如实"          | "关于世界的事实"本身需要判断，原件要么几乎为空，要么写入时就要做大量判断，这正是 K1 的源头；"原文如实"可以机械地保证         |
| 执行时声明的目的放在原件                                      | 移到判断与经验           | 原件要能独立还原，不含思路和目的                                                       |
| 线程、参数溯源、消费关系三种还原过程的机械关系                           | 拆开归位              | 它们描述探索路径，本身就是思路。可核对的部分（执行者、会话、时间顺序、读取操作）留在原件；分叉和消费的解读放在判断；参数溯源可再生，放在框架 |
| 原件"最小可核对"                                         | 改为"最小可独立成立"       | 参照测量记录，自带对象、条件、方法、结果和边界                                                |
| "仅从底层就能建立上层的逻辑"                                   | 改为向下锚定            | 如果能建立，就不应该有上层                                                          |
| 以问题为聚合点                                           | 拆成三部分（第 5 节）      | 问题同时是历史事实和框架                                                           |
| 判断层也复核、裁决冲突 | 不采用 | 判断只记录当时认为了什么，依据真实即成立；裁决放在框架 |
| "对象或问题的当前状态"作为单独一类框架内容 | 取消 | 它就是实体页和综合页本身的内容 |
| 来源摘要页、导航里每份原件一行说明 | 取消，只对原件建检索索引 | 有检索时，直接检索原件内容比检索一句抽象说明更准，还会增加 AI 工作量，摘要也容易被误当作依据。Karpathy 的 index.md 是为没有检索系统的小规模 Wiki 设计的 |
| 概览页 | 不维护，用时从关系图查询生成 | 检索入口由综合页摘要承担，聚合与层级由图中的边承担；少一份会过时的内容 |
| 综合页与对比页分开 | 合并，对比作为综合页的一节 | 对比总服务于一个问题；放在一起检索不会只命中半边，AI 也能拿到完整上下文 |
| 冲突组和裁决作为单独结构 | 由关系图承载 | 冲突是边，裁决是带理由和复核状态的边，冲突组是对图的查询 |
| log 作为框架页 | 归到原件 | 它是只追加的操作记录，就是第 2 节的轻量过程日志 |
| 非文本原件的描述合入实体页或概念页 | 单独挂在原件上 | 与原件一一对应，检索要命中具体文件；一份原件常涉及多个实体；原件变化时可以精确作废 |
| 地位的量化自动排序 | 挂起 | 收益不明确，又增加复杂度 |

关于图结构：所有关系统一放在框架层的关系图中，按来源区分地位，见第 11 节。判断层自身记录的关系（第 4 节）仍属于判断，图中只是它的投影。

## 9. 挂起与待讨论

- **文献新版本**：例如预印本出了 v2，引用旧版本的框架条目要不要标记，怎样检测两个版本的差异。
- **框架条目的依赖传播细节**：遍历上限、重建时机（第 11 节已定原则）。
- **地位的量化自动排序**（挂起）。
- **稳定引用的写法。**
- **人的第一手观察、指令、约束、决定**的依据来源和地位。作者如何记录已定（第 13 节第 3 条），依据来源属于哪一类仍待定。
- **可信度**：体系见第 12.4 节；独立重复如何计入、量化打分仍挂起。
- **约束和决定如何强制生效。**
- **原件的存储保护**（用户认为太细，挂起）：
  - 已列出的方案：保留登记、只读和权限、同一卷上的硬链接、对象存储的版本控制和对象锁定、快照或块克隆、搬移入库。
  - 原则：原件丢失时标为"依据已丢失"，依赖它的判断降为"无法复核"；受限数据只存指纹和说明。
  - 工业场景中大文件占比大，只有数据保存下来，事后才能追溯。
- **记录成本。**

## 10. 评测候选

- **冷读者测试**：只看一条原件和一步关系，能否回答"是什么事、怎么找到的、在哪条线里"。
- **MINT-Eval** 的维基修订和代码提交两个子集：检验按对象和时间精确过滤、判断的演变（FIELD-SURVEY 第 17 节）。
- **ALCOA+**：作为原件规则的检查清单。

## 11. 框架层

框架层回答"现在该信什么、该怎么理解"。它全部可以再生或可以丢弃，永远不能作为依据（规则 ①）。

### 11.1 包含什么

| 内容 | 是什么 |
|---|---|
| **关系图** | 核心。连接实体、原件和判断，承载各类关系和地位，也承载聚合与层级（问题和子问题、属于哪个项目） |
| **实体页、概念页** | 一个对象（设备、系统、材料、人）或一种方法、现象、术语的当前理解：哪些判断在什么条件下成立，附上关于它的原件记录时间线。单独成页，因为同一个对象会被多个主题引用 |
| **综合页** | 以一个问题为中心的完整文档，见 11.3 |
| **检索索引** | 全文、向量 |
| **非文本原件的描述** | 只为图片、波形、数据集、二进制等没有文字可检索的原件生成，挂在那份原件上，标为 AI 所写 |

不设：来源摘要页、概览页、单独的对比页；log 归到原件。理由见第 8 节。概览在需要时由关系图查询临时生成，不保存。

### 11.2 关系图

图中每条边按来源分三种：

| 来源 | 例子 | 地位 | 能否再生 |
|---|---|---|---|
| 判断层已有的关系 | 某人明确写的"A 反对 B，因为……" | 判断层的投影，引用那条判断，地位等同于它 | 能 |
| 原件的机械关系 | 同一对象、同一会话、时间先后、"这条判断读取了那份原件" | 可以核对的事实 | 能，按规则抽取 |
| 框架自己推断的关系 | AI 判断出的"可能矛盾""可能替代""相似""类比" | 标为 AI 推断，带复核状态 | 是框架内容；复核确认后写回判断层，转为第一种 |

**每个节点和每条边的地位坐标**：

- 两个轴：综合程度（原件、判断、框架）和依据来源（亲自执行、外部报告、推断或讨论）；
- 边的来源：上表三种；
- 复核状态：AI 生成 / 人已复核 / 被驳回；
- 时效：有效 / 输入已变化 / 被替代；
- 依据完整性：完整 / 截断 / 只读了一部分 / 权限受限；
- 当前可信度：由支持边、反驳边和写入时可信度重新计算。

AI 按第 6 节第 ⑤ 条的默认展示顺序，加上这些标注来理解优先级。量化自动排序挂起。

**冲突与裁决由图承载**：

- 冲突：一条"可能矛盾"边（AI 推断）或"反对"边（判断）；
- 裁决：一条"替代"或"条件并存"边，带理由和复核状态；
- 冲突组：对图的查询，不单独存储。

框架层的冲突由 AI 自动裁决，再由人工复核。"所以现在该怎么理解"的结论文字写在实体页或综合页里，引用图中的边。

图用数据库还是 Markdown 关系页存储，属于实现问题，后定。

### 11.3 综合页

- **粒度**：一个能独立回答的研究问题或排查目标，相当于一篇论文的主问题，子问题写在页内。一页里出现两个互不依赖的结论，且各节不再共享证据和对象时，就拆分；两页总在互相引用、一起被读时，就合并。
- **形态**：人可以完整阅读的文档；与研究相关时，尽量是一篇结构完整的论文，同时保留错误尝试和其他可能有用的信息，并提示可能有误的地方。
- **结构**：
  1. 问题与背景；
  2. 当前结论，每条标出地位；
  3. 证据，引用判断和原件；
  4. 尝试过的路线：包括失败的路线、停止原因、什么条件下值得重新打开；
  5. 对比：几个方案或假设并排比较；
  6. 未解决的部分和缺口；
  7. 可能有误的地方：依据只来自推断、只有一个来源、AI 推断尚未复核、依据已经变化；
  8. 相关：其他可能有用的信息、类比、相关页面。
- **自带摘要**，摘要用于建索引。
- **风险**：综合页框架性最强，最容易造成框架污染（K2）和思路变窄（1.8），所以探索模式下要能绕过它，直接看原件和判断。

### 11.4 变化的传播

判断层不回头修改，所以变化的传播只发生在框架层：

- 每个框架条目（页面、AI 推断的边）**生成时记下输入清单**，直接指向不可变单元：原件的读取记录、判断的某个版本。底层只追加，引用自然就是版本。
- 新判断写入时，如果涉及某个框架条目的输入或对象，就把这个条目标为"输入已变化"，由 AI 重新综合，结果进入人工复核。
- 只降不升：依据被推翻，下游一律标记；依据被加强，不自动提升下游。

依据：现有系统都没有完整做到依赖传播（Graphiti、Mem0、A-MEM、GraphRAG 不传播；Veracium 整份删除视图；gbrain 记录了完整的输入清单，但只在清除时使用）。

## 12. 索引、导入与可信度

### 12.1 索引

- **原件尽量遵从原文，导入时建立足够细的索引。**按原文的自然边界切：段落、小节、表格、图注，每段带上它在原件中的位置，供读取记录定位。原件本身不拆。依据：Memory Tax 发现按自然边界切块最好，切得更细几乎没有收益，不顾边界的固定窗口最差。
- **任何一层写入后，立即重建受影响的索引条目。**每个索引条目记下它根据哪个版本建立；检索时，版本不是当前版本的条目一律不返回，避免旧索引残留。参考 gbrain（内容哈希变化即重新切块，未重建完的文本不进入检索）和 Veracium（写入计数器）。
- 原件和判断只追加，不会产生旧内容；需要清理的是被改写的框架页和被作废的 AI 推断边。被替代的判断仍可检索，但带"已被替代"标注返回，不删除。

### 12.2 导入时维护框架

> 修订（[设计稿 09](../design/09-digesting-external-sources.md) D-01，2026-11-12 用户确认，2.0.19 实现）：外部原件（文献、厂商资料、网页）登记后要经过一次"消化"，把其中的论断写成判断；本地实证与推断类原件仍按本节，在实际使用时才写判断。

导入一份原件时，AI 做三件事，**不写判断**（判断仍在实际使用时才写，第 2、3 节），**不新建综合页**：

1. **连接**：把原件中提到的实体和概念连到图中已有的节点，方法见 12.3。
2. **更新已有页面**：在相关实体页、概念页的时间线上追加一条指向这份原件的记录；只有实质改变了理解时，才标为"输入已变化"，触发重新综合。
3. **新建页面要过门槛**。满足任一条件才新建实体页或概念页：
   - 已在两份以上原件中出现；
   - 与某个进行中的问题相关；
   - 用户标记过。

   否则只在图中建一个节点和一条"提及"边，不建空壳页。

原件涉及某个已有问题时，只把那份综合页标为"输入已变化"。实体页里写"该文献报告了 X"，属于框架引用原件，地位为"外部报告 × 框架、AI 生成、未复核"。

其他系统的做法：

| 系统 | 导入时做什么 | 新建页面的门槛 |
|---|---|---|
| Karpathy | 写来源摘要页，更新实体页和概念页，刷新 index 和 log，一次涉及 8 到 15 个页面 | 没有明确门槛 |
| gbrain | 识别提到的实体：已有页面的在 timeline 追加，实质改变才改写 compiled truth；没有页面的先过显著性门槛 | 只为值得跟踪、有实际内容的实体建页，不建空壳页；不够格的只保留行内引用；投入分三档 |
| GraphRAG、Graphiti、Mem0 | 自动抽取实体和关系，直接进图 | 没有门槛 |

### 12.3 术语连接

由 AI 先连接，拿不准的进入控制台（便于人机交互的地方）的待决策列表。

| 档 | 情况 | 处理 |
|---|---|---|
| 确定 | 标识精确对上，例如设备编号、DOI，或别名表中已登记的叫法 | 直接建机械关系边，不需要复核 |
| AI 较有把握 | 只有一个合理候选，条件也对得上 | 建 AI 推断边，标"未复核"，可以用于综合；控制台汇总列出，供人批量确认 |
| 拿不准 | 有多个候选、术语有歧义、条件冲突，或这条连接会让很多页面被标为"输入已变化" | 不建边，或只建不参与综合的候选边；进入待决策列表，列出各候选和原文片段 |

- **"拿不准"按可检查的结构条件判断**：候选数量、歧义、条件冲突、影响范围。不靠 AI 自报的置信度，因为自评不可靠（Memory Reward Inflation：模型认可了自己 31% 到 41% 的错误）。
- **人的决定写回判断层**（第 4 节），**同时加入别名表**，下次同一叫法直接落入"确定"档。
- **不阻塞导入**；待决策列表按影响范围排序。

### 12.4 可信度体系

**依据来源 × 综合程度两个轴已经代表了大部分可信度。混合来源继承全部来源**：一条判断既来自文献又来自本地实验，就同时带上两者。规则 ② 照旧：只有全部依据都来自亲自执行，才能称为"我们验证过的"。

| 层 | 内容 | 何时确定 | 放在哪里 |
|---|---|---|---|
| 1. 双轴定位 | 依据来源 × 综合程度 | 写入时 | 条目自身 |
| 2. 写入时补充 | 外部报告再细分（同行评议、预印本、厂商资料、网页）；依据完整性；人还是 AI 写的；是否包含亲自执行 | 写入时，之后不变 | 判断（第 4 节） |
| 3. 当前状态 | 时效（有效 / 输入已变化 / 被替代）、复核状态、支持边和反驳边 | 随时变化 | 框架，重新计算（第 11.2 节） |

**默认排序：逐级比较，不打分**，可解释、无需调权重：

1. 排除"被驳回""已被替代"的条目；
2. 按依据来源：包含亲自执行 > 外部报告（同行评议 > 预印本 > 厂商资料 > 网页）> 推断；
3. 按综合程度：原件 > 判断 > 框架；
4. 看复核状态和有无反驳。

**混合来源按其中最强的来源排序，但标明"混合"并列出全部来源。**打分式量化仍挂起。

此排序用于筛选和推荐顺序，与第 6 节第 ⑤ 条的默认展示顺序一致，是它的细化。

## 13. 谁写什么

**总原则**：描述可信度的字段，不能由被描述的一方来填（Veracium 0031）。AI 只写内容和它引用了什么；能由规则推出的，一律由系统写。

| 内容 | 系统按规则自动写 | AI | 人 |
|---|---|---|---|
| 过程日志：操作、输出、捕获时能自动获得的条件 | ✓ | | |
| 读取记录：哪份原件、哪个版本、哪个范围 | ✓ | | |
| 机械关系边：同一对象、同一会话、时间先后；别名表命中的术语连接 | ✓ | | |
| 条目的作者和写入时间 | ✓ | | |
| 判断的写入时可信度：来源类型、是否包含亲自执行、依据是否完整 | ✓ 由引用的条目推出 | | |
| 判断正文，以及它引用了哪些条目 | | ✓ | ✓ |
| "反对"判断 | | ✓ | ✓ |
| 更正、撤回、"原件有缺陷" | | | ✓ 只有人（第 4 节） |
| 复核结论；术语连接的决定，并加入别名表 | | | ✓ |
| 框架：综合页、实体页、AI 推断的边、非文本原件的描述 | | ✓ 生成 | 复核 |

三条具体规定：

1. **写入时可信度由系统推出。**（2.1 起改为读取时推出、不落盘，见设计稿 10 D-05、D-12。）AI 写判断时只给出正文和所引用的条目；来源类型、是否包含亲自执行、依据是否完整，都由系统根据被引用条目的双轴定位和边界字段计算；作者由系统记录。AI 无法声明自己的判断可信。
2. **原件事实记录的对象和条件**：
   - 捕获时能自动获得的，由系统填，例如执行的机器、时间、命令参数；
   - 需要 AI 归一化的，例如把"2 号泵"对齐到某个设备编号，按第 12.3 节术语连接的三档处理；
   - 没有原文依据的，标为缺口，不补写（第 3 节）。
3. **人说的话被 AI 记下时，作者记为 AI。**
   - 人的原话本来就在对话原件里。
   - AI 据此写的判断（例如把"别动 3 号阀"写成一条约束），作者是 AI，并引用那句原话。
   - 人确认之后，才成为人的判断，写成一条新判断（第 4 节）。
   - 依据：AI 转述时会改写言语行为，例如把"建议这样做"记成"已经这样做了"（Veracium 0038：指令被抽取成"用户做过"占 29%）。
