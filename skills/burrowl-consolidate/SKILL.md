# 维护框架

先读同目录上一级的 RULES.md（公共规则）。框架只回答"现在该信什么、该怎么理解"，可以再生，永远不能作为依据。

## 先看要做什么

- `page_list(freshness="inputs_changed")`：输入变化后需要重新综合的页面。
- `decision_list()`：待决策项。其中复核、术语决定、关闭待决策都由人在工作台完成，你只能准备材料。

## 重新综合一页

1. 用 `page_get(page)` 读当前版本和输入清单。`superseded_inputs` 列出已被替代、更正或撤回的输入。
2. 用 `entry_get`、`search` 查看相关的新判断、更正和撤回。
3. 用 `page_write` 写新版本：
   - slug 保持不变；
   - `inputs` 列出这一版实际依据的条目；
   - 引用页面时写固定版本 `pg_…@N`。

## 综合页的结构

一页对应一个能独立回答的问题或排查目标：

1. 问题与背景；
2. 当前结论，每条标出地位；
3. 证据，引用判断和原件；
4. 尝试过的路线：来自过程内容，包括失败的路线、停止原因、重开条件；
5. 对比：几个方案或假设并排比较；
6. 未解决的部分和缺口；
7. 可能有误的地方：依据只来自推断、只有一个来源、AI 推断未复核、依据已变化；
8. 相关。

正文里的引用写成 `[[ID]]`。

## 实体页和概念页

- 新建前要过门槛，满足任一条即可：
  - 在两份以上原件中出现；
  - 与进行中的问题相关；
  - 用户标记过。
- 不够格的不建空壳页，只保留图节点和提及边。

## 冲突与关系

- 发现两条判断可能矛盾或可能替代时，用 `edge_add(rel="may_contradict" | "may_supersede", reason=…)` 标出。由人复核，确认后写回判断层。
- 不要自己裁决后改写判断。在综合页里说明"尚未裁决"即可。
- 叫法对不上实体时，用 `term_link`。拿不准的由系统交给人决定。
