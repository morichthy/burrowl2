# burrowl 公共规则

所有 burrowl Skill 共用。工具来自 MCP 服务 `burrowl`，工具名把点换成下划线，例如 `judgment.write` → `judgment_write`。

## 1. 三列

| 列 | 是什么 | 能否作为依据 |
|---|---|---|
| 原件 | 原文如实：文件、文献、对话、过程日志、事实记录 | 能 |
| 判断 | 当时谁、依据什么、认为了什么 | 能，系统会标明来源 |
| 框架 | 实体页、概念页、综合页、关系图 | **永远不能** |

依据来源分三类，彼此没有固定高低：**本地实证**（在本项目内执行、测量或直接观察）、**外部报告**（文献、厂商资料、网页）、**推断**（推理、讨论或 AI 生成）。只有全部依据都是本地实证时，才能说"全部依据为本地实证"。

判断只有三种类型：

| 类型 | `kind` | 写什么 | 规则 |
|---|---|---|---|
| 结论 | `conclusion` | 关于对象的陈述 | 可以作为依据 |
| 过程 | `process` | 提问、尝试、停下的路线（`reopen_condition` 写重开条件）、目的 | **不能作为结论的依据**；探索模式默认不返回 |
| 规定 | `normative` | 约束、决定、指令 | 检索时排在最前，动手前必须检查 |

转述外部材料（文献、厂商资料、网页）中的发现时，仍写 `conclusion`，填 `external_author`（原作者）；说明里显示"转述 · 原作者 …"。它能作为依据（有原件出处），但地位是外部报告，永远不能称为"我们验证过的"；本地验证后，它的现状里会出现"被佐证（本地实证）"。

**条目、关系、坐标**（设计稿 10）：

- **条目**有稳定的 ID，版本写 `@n`（`jdg_…@3`、`art_…@2#p3-2`）；不带 `@n` 指当前版。改写写成新版本，旧版本仍在，引用固定在你当时引用的那一版。
- **关系**是"主语—谓词—宾语"，一条一行，两端固定到版本，从两端都查得到（"依据了 / 被依据"）。依据写在 `cites`；其他关系写在 `relations`，先从核心谓词选：`supports` 佐证（本条事后为对方作佐证）、`opposes` 反驳、`answers` 回答、`targets` 针对、`coexists_under` 条件并存（必须写 `condition`）。核心谓词都不合适时用 `relates` 并写 `label`（如「导致」「是……的一种」）；系统不赋予它含义、不算依据，人会定期归并常用标签。`supersedes`（替代）只能由人确认。
- **坐标**由系统在读取时推出，你不能声明。按"地位 → 类型 → 现状 → 说明"读：**地位**是综合程度（原件 / 判断 / 框架）× 依据来源，只由这一版自己的依据决定；**类型**是 `kind`；**现状**是有效性（当前有效 / 被替代 / 已撤回 / 已退役 / 依据失效）、复核与现状标记（被佐证、被反驳、依据有变化、部分依据已失效……）；**说明**是作者、原作者与说明标记（依据含未确认的识别、转述但没写条件、结论没有依据……）。每个标记都带出处 `via`：造成它的那条关系和另一端，`entry_get` 里可以看全。

撤回、标缺陷、退役原件是人对某一版的处置，记在版本上，你不能做。复核也不是判断，记在被复核条目那一版的历史里。

## 2. 你能做什么、不能做什么

- **能做**：记过程（`capture_log`）、登记原件（`artifact_register`）、读原件（`artifact_read`）、看原件页面并提交识别的文字（`artifact_view`、`artifact_extract`）、升级事实记录（`record_promote`）、写判断（`judgment_write`）、写框架页和推断的边（`page_write`、`edge_add`）、连接术语（`term_link`）、检索（`search`、`search_exact`、`search_associate`、`entry_expand`、`timeline`，策略见 burrowl-read）；定期巡检时领取巡检包、提交巡检发现，或作为复核员复核发现（`inspection_get`、`inspection_submit`、`review_ai_submit`，见 burrowl-inspect）。
- **不能做**：
  - 更正别人的判断、撤回判断，人的复核，决定术语，标记或取消缺陷，退役、替换、删除原件——这些只能由人在工作台完成。你自己会话写的判断可以用 `judgment_write` 的 `revises` + `revise_reason` 改写成新版本；
  - 你可以做 **AI 复核**（`review_ai_submit`）：对照原件层、判断层核对一个 AI 生成未复核的框架页或关联边（设置允许时还有依据已变化的判断）。依据只能是本会话读过的原件段落、事实记录、判断，不能是框架页或边；不能复核本会话自己写的；拿不准就交 `unsure`。结果记为"AI 已复核"，不等于人已复核。觉得某个条目需要人看，用 `review_request` 加入待决策；
  - 声明坐标——依据来源、现状、标记都由系统从依据与关系推出；
  - 标记本地实证（`local_observation`）——只有人能标；你的执行要用过程日志和事实记录留痕；
  - 读取人标为不外发的原件——巡检运行里会得到 `NOT_OUTBOUND`，不要设法绕过。
- 日常工作中，有值得留存的异议时，写一条新判断，并用 `relations: [{rel: "opposes", target: <ID>}]` 指向它。

## 3. 写判断

- **值得留存才写入。** 判断层只收录日常工程、科研及其他重要或经常性工作中，对后续理解、决策或复用有价值的经验、判断和规定。过程判断也遵守这个原则。
- 引用固定在你实际核对的条目版本：写入时系统把不带 `@n` 的引用补成当时的当前版。所引条目后来出了新版本，你的判断会带"依据有变化"标记（出处写着当前版），依据来源不变；采用新版前重新核对。撤回、取消撤回和重新生效由人处理。
- **一条判断要做到的四件事**（按这个顺序要求；过程判断可以放宽后三项，仍要写清对象和条件）：
  1. **有价值**：对后续理解、决策或复用有意义，才写。
  2. **原子化**：只写一个可以分别成立、也可以被反驳的论断。两个意思就拆成两条，用 `supports` 等关系连起来。
  3. **可复现**：别人只凭这一条，就能照着重做、重算或重新核对（见下面"可复现"）。
  4. **不带框架性措辞**：不写「显然」「关键在于」「根本原因是」；归纳放到综合页。
- **单独拿出来也能看懂。** 检索结果、关系图、复核页常常只显示这一条的正文，读的人看不到当时的对话。写完自问：只给这一段，别人能不能说清"关于什么、在什么情况下、结论是什么、有多大把握"？
  1. **对象写全称**：写"2号泵""V-301 入口阀"，不写"它""该设备""上述方案"；对象同时填进 `objects`。
  2. **数值带单位和含义**：写"出口压力 0.82 MPa（压力表 PG-12，10:05）"，不写"偏高""明显升高"。
  3. **标明性质**：实测、文献报告（填 `external_author`）、推测，用词区分；把握程度写在措辞里。
  4. **不用依赖上下文的说法**：「如上」「同前」「本次」「刚才」；写具体日期、版本、文件。
- **专有量和术语要在正文里展开，并引用定义它的原文段落。** 例如"达标轮数"要写成"损失与最终值之差首次小于 0.01 的轮数"，并在这句后面写 `[^n]`，让 `[^n]` 对应一条 `role="定义"` 的依据，指向原文里定义它的那一段。不要让读的人去查。
- **可复现。** 凡是描述做法、实验、测量、配置或排查步骤的判断，写出别人动手要用的东西：对象与设备（型号、编号）、起始状态、具体操作和参数（数值、单位、顺序）、判定标准（看什么、多少算成立）、用到的文件和版本（脚本、数据、配置，`cites` 引用）。当时没记下的写"未记录：……"，不凭记忆补全。步骤很长时，完整过程留在过程日志（`capture_log`）和原件里，判断写"做了什么、关键参数、怎么判定"并引用它们，不要整段复制。纯观点、规定没有可复现的操作，不适用这一条。
- **正文和条件里能抽出的关系，都要建立成关系。** 写完判断后通读正文和 `conditions`，凡是用到的、能连到某个条目的内容，一条一条建立关系，不要只写在文字里：
  - 用到的原件段落、事实记录、过程日志、别的判断，写成依据 `cites`；
  - 支持、反驳、回答、针对别的条目、条件并存，写在 `relations`（`supports`、`opposes`、`answers`、`targets`、`coexists_under`；都不合适才用 `relates` 加 `label`）；
  - 涉及的设备、对象，填 `objects`；
  - 条件是从某份材料里来的，也要引用那一段，作用写"条件"。
- **每条关系都要写说明。** 每一条关系（不只是依据）都带 `why`（一句话：为什么连这一条，这一段在这条判断里起什么作用），可以再加 `role`（作用）。`role` 自由填写，系统只给建议：依据可用"定义、方法、数据、条件、直接依据、背景"；佐证可用"数值一致、方法不同但结论一致、条件更宽"；反驳可用"数值冲突、条件不同、方法不同"。系统不会因为没写说明而拒绝写入，但这是对你的要求：没有说明，读的人和复核的人看不出这一段为什么在这里。
- **正文里引用用 `[^n]`，不建议用 `[[ID]]`。**
  - `cites` 的每一项（可以是引用字符串，也可以是 `{ref, role, why, marker}`）都会对应一条关系。
  - 正文里在对应的句子后写 `[^1]`，对应关系的 `marker` 写 `"1"`；同一个编号可以对应多条关系（一句话引用了两处）。
  - 系统在写入时检查：正文里的每个 `[^n]` 都有关系对应；带 `marker` 的关系，它的编号也出现在正文里。对不上会拒绝写入，请改正后再写。改写判断时整体重新检查。
  - 不建议在正文里写 `[[ID]]` 来引用：它虽然会被系统自动并入依据，但没有 `why`、`role`，也看不出哪句话对应哪条。只有想在正文里"提到"某个条目（如"见 [[jdg_…]]"）时才用，并把它当依据时仍要用 `cites` 补上说明。
- **模糊但有价值的论断可以写，但要把边界写清。** 适用范围还不清楚时：`conditions` 里分别写明**哪些使用条件已经清楚、哪些还不清楚**，并在写入时设 `scope_unclear=true`。这个 flag 是你写入时的声明，系统不会替你判断；读的人看到"适用范围未明"会把它当线索，不过分相信。范围清楚的判断不要设这个 flag。

  | 反例（没头没尾） | 正例 | 差在哪里 |
  |---|---|---|
  | 压力波动偏大，可能是气蚀。 | 2号泵出口压力波动 ±0.05 MPa（V-301 开度 60%，2026-11-03 10:00–10:05，压力表 PG-12）；推测可能与入口气蚀有关，尚未验证。 | 缺对象、数值、工况；"可能"没有说明依据。 |
  | 该方案在高温下失效。 | 方案 B（硅胶垫片）在 180 ℃ 持续 2 小时后密封失效（试件 3 个，均漏）；未测 150 ℃ 以下。 | 指代词；"高温"没有数；样本量和未覆盖的范围没写。 |
  | 如上，调整后恢复正常。 | 2026-11-03 将 V-301 开度从 60% 调到 80% 后，2号泵出口压力波动降到 ±0.01 MPa（连续 30 分钟）。 | "如上""调整""恢复正常"都要翻上文才懂。 |
  | 方法 A 比方法 B 收敛更快。 | 在数据集 D、初始化相同、学习率均为 0.001 时，方法 A 的达标轮数为 20，方法 B 为 31[^1]；达标轮数指损失与最终值之差首次小于 0.01 的轮数[^2]。（`[^1]` 依据结果文件的那一行，`[^2]` 依据文中定义该指标的段落，`role="定义"`。）示意例子，数字不是真实数据。 | 没有展开"收敛"与"更快"的定义，也没有引用定义；别人无法核对。 |
  | 综述认为气蚀与入口压力有关。 | 离心泵入口压力不足时容易发生气蚀，表现为出口压力脉动增大并伴随噪声（转述，原作者：某文献；条件：离心泵）。 | 没有说明是转述、谁说的、在什么对象上。 |
  | 调了阀门之后压力稳定了。 | 2026-11-03 将 2号泵入口阀 V-301 开度从 60% 手动调到 80%（每次 5%，间隔 2 分钟），稳定 30 分钟后用压力表 PG-12 读出口压力：波动 ±0.01 MPa（此前 ±0.05 MPa）；判定标准：波动小于 ±0.02 MPa 视为稳定。依据：操作日志（`cites`）。未记录：泵转速。 | 不能照着做：不知道调哪个阀、调多少、怎么读、多少算稳定。 |
  | 该材料在 150 ℃ 下抗拉强度下降。（条件为空） | 条件："已知：试样 S1，拉伸速率 5 mm/min，150 ℃ 保温 30 min；不清楚：其他温度、其他批次。"，`scope_unclear=true`。 | 范围不清楚却没有声明，读的人会当成普遍结论。 |

  正例不必写满：该写的是**别人要用这条判断时必须知道的**。写不全的项，写成"未记录"或"原文未说明"，比省略好。
- `cites` 优先填原件段落：`artifact_read` 返回的 `cite_as`，如 `art_…#p3-2`（PDF、PPT 第 3 页第 2 段）、`art_…#seg-4`（文本、Word）。也可以填原件、事实记录或判断的 ID。
- 引用的段落要先读过；没读过就引用，写入会成功但返回 `UNREAD_CITATION` 提示，并出现在工作台的状态检查里。
- 引用或支持一条**待复核**的判断（它引用的原件段落已变化，还没有人复核）会成功，但返回 `RECHECK_CITATION`：它的依据可能已不成立，先回到原件核对，或改引原件段落。
- 有的原件已由人**退役**（不再单独出现，例如旧的派生文本已由原件自己的抽取层取代）。引用它（包括经它的读取记录、从它升级的事实记录间接引用）会成功、依据来源不变，但返回 `RETIRED_CITATION` 提示：请改引替代它的原件（`entry_get` 的版本历史里 `replaced_by`，或退役理由）。依据全部来自已退役原件的条目有效性为"依据失效"、默认隐藏；部分依据失效的现状里有 `basis_lapsed` 标记；人删除原件后，指向它的引用显示为"已删除"。你不能退役、替换或删除原件；发现重复或缺陷时，可请人复核。
- 原件的文字来自它的抽取层，每段带可信度档：原样复制、解析文字层、人工转写、OCR 识别、AI 识别。OCR / AI 识别且未经人确认的段落，引用前用 `artifact_view` 对照原件页面；引用时会返回 `LOW_FIDELITY_CITATION` 提示，并写明这一块是未复核、AI 核对一致还是 AI 认为有问题；写入照常成功，判断的说明里会标"依据含未确认的识别"（人确认后自动消失）。公式或文字对结论很关键时，写判断前后用 `artifact_view` 对照原图再检查一次，有误用 `artifact_extract` 更正后再改写判断。
- 结论和规定里不写框架性措辞：「显然」「关键在于」「根本原因是」「目前有三种思路」。归纳和组织放到综合页里；过程内容记录思路与尝试，可以有这类说法。
- 结论的 `cites` 不能填过程内容（提问、尝试、停止）。思路不是证据；需要依据时，引用过程内容背后的原件或结论。
- 不知道的就写明不知道。只有值得持续追踪、会影响后续工作的未决问题，才作为过程判断留存。
- 人在对话里说的话，你记下来时作者是你；它在人确认前不是人的判断。不要把"建议这样做"写成"已经做了"。

## 4. 按地位使用判断

检索结果的 `status_note` 与坐标（地位 → 类型 → 现状 → 说明）写明了依据来源、复核状态和标记。按它决定信几分、要不要回原文、要不要本地验证：

1. **可以直接用**：依据全部为本地实证，或人已复核。
2. **可以用，说明来源**：外部报告（同行评议）。条件要对照自己的情况。
3. **当作线索**：预印本、厂商资料、网页、只有一个来源、AI 推断未复核、"转述但没写条件"、"依据有变化"、"被反驳"。
4. **回原文**：结论要用于动手、决策，或要写成新结论的依据时，凡是第 3 类，先 `artifact_read` 读它引用的原文，核对条件与原意。
5. **本地验证**：要用于动手或决策，而依据只有外部报告或推断，本地又能做时，向用户建议本地验证；做了就用 `capture_log` 留痕，写本地结论，用 `supports`（佐证）或 `opposes`（反驳）连到原来的结论。原结论的地位不变，现状里会出现"被佐证（本地实证）"或"被反驳"。
6. **外部结论与本地实证冲突**：写 `opposes` 留下记录，不删除、不忽略；当前做法以本地实证为准，并说明条件差异。
7. 文献和报告很少给出完整条件。使用转述的结论前，对照自己的对象和条件；只想看本地实证时，`search` 用 `source="local"`；只看转述的用 `quoted=true`。

## 5. 约束

对设备、阀门、系统等对象动手前，先调用 `constraints_check(objects=[...])`。检索结果最前面列出的约束、决定和指令，必须遵守。

## 6. 过程与条件

- **原件也有收录门槛。** 收录能支撑核对、复现或后续复用的材料与实际过程，保留真实出处。例行操作、临时对话和巡检流水留在日志或当前会话；其中个别片段有独立价值时，才明确选择收录。
- 值得留存的操作和测量用 `capture_log` 记录，`conditions` 只记当下能确定的。用到的文件（脚本、输入数据）写进 `inputs`，产出的文件登记后写进 `outputs`，或登记时用 `produced_by` 指向这条日志。出处由此记在原件自己身上，不另写说明。
- 事后升级为事实记录时不能补写条件；缺失的写进 `gaps`。
- **事实记录要能单独复核**：`method` 写到一个不知道目的的人也能复现或核对为止，即数据怎么产生、各组怎么设置、结果里每个指标和术语怎么定义。这些是定义，不是思路，应当写全。每个定义要用 `cites` 指向原件里写着它的段落（例如脚本中定义指标的几行），找不到原文的写进 `gaps`。不写目的、不写与别的来源的比较。
- `gaps` 只写"哪些条件当时没记下"或"哪些部分没有覆盖"，例如"只用了一个随机种子"。"不是文献用的数据集"这类话依赖目的，属于判断或过程内容。

## 7. 复用与探索

- 复用已有经验时，用 `search(mode="reuse")`。
- 探索新路线、想避免被已有结论锚定时，用 `search(mode="explore")`。这个模式不返回框架页，默认也不返回过程内容（需要时加 `include_process=true`）；`entry_expand` 也不返回解读。
- 结果中现状为"被替代"的条目只作为历史参考。命中旧版文字时结果带 `old_hits`（旧版引用、命中段落、改动理由）；需要时用 `entry_get` 读那一版。
- 每条结果带全部关系 `links`（出边 `out`、入边 `in`，每条 `{p, ref}`）：顺着依据、被依据、佐证、反驳继续找；超过上限时写明还剩多少，用 `entry_get(ref, links=谓词)` 取全。
- 检索结果的名次只表示相关度，不表示可信；可靠与否看每条的 `status_note` 与坐标。
